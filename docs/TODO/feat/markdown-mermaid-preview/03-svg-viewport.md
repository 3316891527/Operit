# SVG 显示范围与缩放修正（历史方案）

后续设备反馈为完全空白，此方案未通过验收，相关页面、脚本和浏览器测试已删除。当前实现见 [原生 Canvas](04-native-canvas.md)。以下仅保留调查历史，不能作为当前实现或测试结果。

## 设备反馈与证据边界

初版安装后，用户反馈普通预览仅显示节点矩形的一部分，全屏缩小后只能在左上角看到很小的图形。生成 SVG 与完整展示图表是两个不同的验收条件，初版仅判断 SVG 存在的设备断言不足。

本次沿用 [PR #230](https://github.com/3316891527/Operit/pull/230) 的贡献分支。原附件不读取、不上传，浏览器场景使用独立编写的流程图和架构图，不包含用户原文档。

源码审阅确认初版只按视口宽度计算适配比例，并将上游 `viewBox` 宽高设为固定像素后叠加 CSS `transform` 和滚动占位容器。该结构没有同时保证纵向内容完整、图形居中或按钮区域不遮挡内容。这些是已确认的实现限制；设备截图的唯一运行根因尚未由几何数据证实。

## 实现

- 等待非零视口和字体就绪，再调用 Mermaid，避免首次布局尚未完成时开始测量。
- SVG 插入页面并完成布局后，用 `getBBox()` 读取实际图形范围，并添加 12 个 SVG 单位的边距。
- 根 SVG 填满有效视口，使用 `preserveAspectRatio="xMidYMid meet"` 同时适配宽高；移除固定像素画布、CSS 缩放与滚动占位容器。
- 底部为缩放按钮预留空间；缩放按钮、鼠标滚轮、双指缩放及单指拖动均更新同一个 `viewBox`。复位恢复完整图形。
- 新源码取消尚未完成的视口等待，渲染结果在每个异步阶段核对请求版本，避免旧结果覆盖新图表。
- 保留原来的 Mermaid 围栏、默认预览、源码切换、复制和全屏入口，内置的 Mermaid 11.17.2 脚本保持不变。

## 回归与验证

新增 `ci/mermaid-preview`，直接加载应用的本地 HTML、控制器及 Mermaid 脚本，共 28 项浏览器场景：

- 9 份图表示例（覆盖 8 种 Mermaid 语法）分别在 380×300 与 380×880 视口检查完整边界、居中与有效占用空间，共 18 项。
- 缩放、拖动、复位与旋转；长图；宽图；上游错误视框；零尺寸视口恢复；语法错误后修改；原生触摸双指缩放；滚轮缩放锚点；取消旧的布局等待；延迟旧渲染结果，共 10 项。

Android Tests 工作流增加独立的 `Mermaid browser geometry` 作业，使用固定版本的 Playwright 和真实 Chromium。每项场景结束后保存合成图表截图与几何 JSON 为 CI 附件。依赖锁定在该目录独立维护，不改变应用 npm 依赖。

现有 `MermaidRendererAndroidTest` 的两项设备测试增加真实边界断言，通过 `getBBox()` 和 `getScreenCTM()` 将图形转换为屏幕坐标，检查整个图形落在有效视口内。

当前 Android 的 Ubuntu/proot 环境可以读取 Chromium 版本，但创建浏览器页面时进程以 SIGTRAP 退出，尚未得到有效截图或几何数据。该环境故障不能证明 Android WebView 中的图表根因。浏览器几何回归未在本地通过，设备 instrumentation 也未执行；CI 发起记录及最终提交链接见 PR，最终结果与真机效果仍需确认。

## Canvas 取舍

Mermaid 同时负责语法解析、文字测量、节点布局、连线路由和 SVG 生成。改用 Android Canvas 需要继续依赖或重新实现这些能力；只替换绘制 API 不能保证尺寸问题消失，也会增加图表类型兼容的维护成本。本次选择先统一现有 SVG 显示坐标，Canvas 保留为独立渲染架构的后续选项。无法从 MT 管理器截图判断其内部使用 WebView、SVG 还是 Canvas。
