## 原因与改动

归档流每次读取都会更新内部字节数，但 150ms 内的连续字节通知会被节流。条目完成通知原先又将 `entryBytes` 清零，因此在 150ms 内完成的文件只有零字节通知；总字节数与完成条目数仍准确，当前文件的最终字节数却丢失了。

完成通知保留该条目的真实字节数，同时清空 `entryTotal`，使完成条目只通过完成数量参与总比例，避免重复推进。下一条目开始时由路径切换重置当前字节数。条目通知仍在输出流关闭和归档条目成功结束之后发出，取消或失败不会提前计数。

引擎时钟支持注入，默认继续使用 `System.nanoTime`，保留原有 150ms 节流。原失败回归固定时钟为零，让字节读取全部处于节流窗口内，稳定覆盖快速文件场景。新增一项真实 ZIP 回归同时核对写入、校验和解压的完成字节、空文件切换、完成数量和比例单调性；已有比例回归增加非零完成字节，防止重复计入下一条目。
