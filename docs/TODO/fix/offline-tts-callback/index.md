# 离线语音试听回调崩溃

设备日志记录了离线 TTS 在音频回调处查找 `invoke([F)Ljava/lang/Integer;` 失败，随后 JNI 带未处理异常进入后续调用，引发 SIGABRT。普通 Kotlin 异常捕获无法阻止该原生终止。

在 Sherpa Kotlin 绑定中为两个回调生成入口统一包装显式回调类，声明 FloatArray 到 Int 的 invoke 方法，并保留 JNI 可见方法。原有语音样本、返回值和停止合成判断不变，不修改模型、原生库或下载协议。

修改保留现有 Kotlin 调用接口，只改变交给 JNI 的运行时对象。修复随 APK 交付，已下载模型和现有离线资源可以继续使用。

验证记录：静态差异检查；本地未运行构建或测试。工作分支派发 Android 构建，结果待工作流完成。设备试听、停止、连续试听仍待新 APK 验证，不能据源码检查记为通过。

## 配套设置修正

离线语音合成的 Speaker ID 改用可搜索的选择面板。打开面板时，在 IO 线程创建独立的模型查询实例，通过现有 getAvailableVoices 和原生 numSpeakers 读取有效编号，查询结束后释放实例。单说话人模型只提供编号 0，多说话人模型按引擎枚举；没有可靠名称映射时显示模型名和编号，不猜测音色名称。加载失败显示错误并允许刷新，不提供任意编号输入。

现有 speakerId 字符串配置和工具接口保持兼容；空值继续表示默认编号 0，无效旧编号可以通过面板重新选择。切换模型时清空上一模型的枚举列表。旧 VITS/Piper 自定义包入口保持原协议，本次只改 Sherpa 离线模型。

语音设置已有完整的内嵌试听区，因此删除重复的独立演示页面、包装器、Screen 对象、隐藏路由注册和专用导航回调，并移除各语言中仅由该页面使用的字符串。共用 TTS 服务、语音档案和内嵌试听继续使用。旧的 hidden.text_to_speech 页面标识不再注册。

新增 JVM 回归源码检查 JNI 需要的精确回调签名、原样转交采样数组和 1/0 继续/停止值。本地不运行测试，执行结果以仓库工作流为准。

## 完整设备回归

1. 选择单说话人模型，打开列表应仅有 0；多说话人模型应列出引擎实际支持的全部编号。
2. 选择音色后离开并返回，配置应保留；切换模型后应显示新模型的列表。
3. 没有模型时应引导先选模型；模型不可用时应显示错误且不列出旧结果。
4. 短文试听应正常发声且不闪退；连续试听、停止和长文停止应保留原有行为。
5. 设置页只保留一个内嵌试听区；独立文本转语音演示页面及隐藏路由不再存在；语音设置和唤醒设置仍可正常打开。
6. 旧 VITS/Piper 包配置和在线、系统 TTS 的配置及试听应保持原有行为。

结果：以上设备用例均待新 APK 验证；未记录为通过。
