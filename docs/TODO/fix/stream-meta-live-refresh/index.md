## 根因与修改

流式 Markdown 的行内代码在换行处结束，但代码示例上下文和 sections 拆分器会跨行寻找闭合反引号。正文出现未配对的连续反引号后，后续工具轮次和实际协议被误认为代码示例。过滤器暂存这些内容，遇到远处的反引号后又将整段作为示例放出。

现在三处使用同一行边界：代码上下文在换行处结束行内状态；过滤器在候选示例遇到换行时立即投影可见正文；sections 拆分器只在本行查找行内闭合标记。合法的同一行代码和围栏示例继续保留。

## 验证

- Kotlin 2.2.21 独立 JVM 编译通过，6 个相关测试类共 39 项通过。
- 覆盖三种提供方、LF/CRLF/CR、逐字符和不同分块、61 轮工具输出、合法示例、保存点、回滚和事件交错。
- 替换实际协议负载后，使用同一份真机消息结构回放。旧过滤器显示 61 个占位协议载荷，逐字符输入最长 253683 字符未产生显示增量；新过滤器显示 0 个载荷，正文在完成前持续发布。
- 同一结构经旧 sections 拆分器得到 1 个普通文本片段，61 个载荷留在正文；新拆分器得到 419 个结构片段，61 个协议均单独保存，普通文本中载荷为 0。新旧 round-trip 均保留完整输入。
- 独立 JVM 编译仅移除三个未使用的 Android 模块导入，事件 DTO 从生产文件原样提取；生产解析实现未替换为测试替身。这不等于完整 Android 构建或新 APK 的真机验收。
- 真实聊天和协议负载不提交到仓库。回归用例使用最小化合成输入，既有数据库只读。

新增回归由原有 Android JVM 测试入口发现，没有新增常驻专项工作流。App 版本不变，手机的 +23 尚未包含此修复。
