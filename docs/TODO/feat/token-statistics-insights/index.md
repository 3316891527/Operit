# Token 用量与费用原生重构

原有统计页把概览、活跃记录、模型和配置堆在同一长页，手机筛选与请求追溯不便。基于已评审的 HTML 设计稿增量实现总览、模型、配置、请求四页，沿用已发布价格规则。统计页使用设计稿的固定配色，明暗跟随应用全局设置。

首轮功能实现已提交至 [PR #262](https://github.com/3316891527/Operit/pull/262)。用户实机反馈后，本轮仅按原稿返工界面；源码与静态核对已完成，远端构建结果与对应 APK 的实际视觉验收待确认。

## 实现范围

- 独立请求日志和数据库 30→31 迁移。成功用量事实、旧累计、定价与迁移完成标记保持原义
- 按真实用途采集来源，保存状态、首字和总耗时以及观测到的尝试编号。历史缺失字段显示未记录
- 数据库筛选分页，分块汇总与现有计价器重算费用，支持周期对比、峰谷与长上下文明细
- 原生四页、日期快捷项与日期选择、图表点击追溯、配置定价、请求详情与 CSV
- 主界面下方的清空及设置入口。清空确认等待五秒，并通过持久 epoch 阻止清空前的在途请求写回

## 验收与交付

手机不执行编译或 JVM/设备测试。完成必要回归源码和静态核对后创建开发 PR，派发远端 assembleDebug 与测试，确认启动后停止轮询。本次没有新的正式发行指令。不得对真实用户数据库执行清空验证。

## 分工

- capture：请求采集、实体/DAO、Repository、迁移与相关回归
- insights：查询 DTO、统计与分页、计价构成与相关回归
- source：真实发送入口的用途和子代理执行模型上下文
- 主代理：Compose、ViewModel、资源、集成检查与交付

## 已核实的数据边界与回归源码

- 来源在实际发送入口传递；限流冷流保存发送时上下文，不能继承后来收集者的用途。子代理只保存实际锁定的执行模型，不细分其任务、思考、工具或正文。
- 记忆向量目前走独立 embeddings HTTP，不经过本轮请求采集边界；不补造对应 Token 日志。旧记录缺少的状态、来源和耗时保持未记录。
- 时间倒序和耗时排序直接使用数据库分页。Token 与费用排序需要逐行读取真实归一化或计价值，写入事务临时排序表，再通过 SQL LIMIT/OFFSET 返回当前页，不常驻全历史。
- 周期比较按当前桶相对周期起点的真实毫秒覆盖平移到对比周期，保持桶数和时长一致；事件按真实发生时间归桶，不做按比例分摊。
- 费用总额始终来自既有计价器。输入总量和分项冲突或投影分项超出总额时，输入费用整体列为无法归类，保留可确定的输出费用，不按比例补造分类。
- 已增加来源冷流、比较桶覆盖、冲突输入费用和旧 Token 归一化排序的回归源码；尚未在本机执行，需远端验证。
