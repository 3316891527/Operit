# Markdown 枚举遗漏导致的编译失败

## 问题

提交 2b7bf8e3 的 Android JVM 工作流在 compileDebugKotlin 阶段失败，尚未执行 JVM 测试断言。WaifuMessageProcessor 的稳定片段边界分类使用穷尽式 when，但没有处理新增的七种 Markdown 类型。

此前纯 Kotlin 核心检查没有编译这个调用方，因此该错误未在本地核心回归中出现。

## 修正

定义列表、脚注、HTML 块按结构块处理，可以形成稳定片段边界；转义文字、高亮、下标与上标按行内内容处理，继续等待句子边界。原有类型的分类保持一致，when 继续显式覆盖全部枚举值。

类型枚举与该边界分类函数分别移动到不依赖 Compose、Android 的生产 Kotlin 文件中，WaifuMessageProcessor 导入并使用同一个函数。包名、类型名称、枚举顺序和调用语义不变。

Markdown 核心检查直接编译真实的枚举与分类函数，新增回归覆盖块级分段、行内内容不提前分段，以及 JNI 节点序号兼容性。以后新增类型遗漏分类时，核心编译阶段即可暴露问题。

## 验证

针对修复运行核心编译与回归、差异检查和仓库规范检查。完整应用的 Build 与 Android Tests 在提交后重新发起，只核对启动与提交，不轮询远程运行进度。

实际生产枚举、边界函数及 Markdown 语法回归已独立编译并运行，20 项 JUnit 测试通过；涉及的 5 个 Kotlin 文件通过 PSI 语法检查，Bash 语法和差异空白检查通过。PSI 不做完整应用依赖的类型解析。
