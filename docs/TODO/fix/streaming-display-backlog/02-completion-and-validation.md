# 完成与验证

## 真实结束与共享流

取消路径会从 replayCache 拼接已接收全文并清除 contentStream，所以取消后全文出现支持显示消费落后的判断。正常完成原本也会清除 contentStream，本次没有找到确定性的遗漏，因此保留该逻辑，不用超时、模拟取消或重新执行工具替代修复。

旧共享流在锁内取得订阅快照、锁外发送，订阅退出可使发送抛出并影响上游。旧 close 同样锁外投递，可能让完成通知越过已接受的文本。现在接受、投递、结束与订阅移除串行，并用待投递队列处理回调重入，保证每个现存订阅收到相同顺序的已接受正文和完成通知。生产者自身取消检查保留，慢订阅及晚订阅仍能获得完整 replay 和失败原因。

## 回归与验证边界

新增 24 项回归源码：JSON 批处理 5 项、节点更新 3 项、共享流投递 6 项、合成工具显示 5 项、native 调度生命周期 5 项。覆盖多工具长参数与结果、三个并发显示订阅、源仍开放时更新、正常结束、切页重订阅、取消、跨块转义与 rollback。并发顺序用例包含可明确构造的重入顺序，其他并发压力用例有执行上限。

native 主线程用例验证调用方上下文与排队消息完成，不把线程调度先后或固定时间阈值当作性能测量。上述用例尚未编译或运行。按仓库执行约定，本地只做静态检查，远端 Debug 与 Android Tests 的启动、构建结果、测试结果和设备执行分别记录。

## CI 编译修正

首轮 PR 检查在编译 `StreamingDisplayBacklogAndroidTest` 时发现，文本块回滚用例调用的 `withRollbackPrefix` 只接受 `Stream<Char>`，导致接收者不匹配，后续传给文本块渲染器时又出现 `Stream<Char>` 与 `Stream<String>` 类型不匹配。

内部前缀包装器与辅助函数现改为保留 `Stream<T>` 元素类型，同一实现支持字符流和文本块流；用例显式声明 `stream<String>`，保留开放工具块恢复与后续结果独立成块的断言。现有字符流调用仍返回字符流，包装仅附加前缀标记，不转换正文或更改收集行为。

`Candidate checks` 汇总必需检查的结果，必需的 Android JVM 检查失败会使它一并失败。修正保留检查要求与全部 24 项回归源码，更新后的编译与运行结果仍交由远端 CI 验证。
