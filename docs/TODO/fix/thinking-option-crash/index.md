# 思考档位保存异常与界面无效写入

## 问题与范围

保存不存在的思考档位时，`ModelConfigManager.validateThinkingOptionId` 会抛出 `IllegalArgumentException`。聊天配置委托在独立协程中直接调用保存操作，没有处理校验或写入失败，导致配置错误传播到进程未捕获异常处理器。

错误发生时的完整崩溃栈由反馈提供，附带导出日志中未找到相同堆栈。不能据此断言日志内某次模型切换就是唯一触发现场。用户快照中另有两处残留 `low`：一处没有思考映射，另一处没有配置模型。快照已独立修复并完成所有压缩条目的 CRC 校验，不纳入仓库。

## 实现

- 保留模型配置管理器的严格校验和 DataStore 事务行为，无效档位不写入，也不改成其他档位
- 将聊天思考设置的保存、成功刷新和失败反馈放入有明确异常边界的协程入口
- 在派发时固定目标配置 ID，避免排队期间切换配置后写入新目标
- 校验失败使用 `OKToast.warning` 显示重新选择提示，其他更新错误使用 `OKToast.error` 显示失败提示并记录日志；取消异常继续传播
- 为真实协程入口增加回归，覆盖拒绝、成功、目标切换、写入失败、刷新失败及保存或刷新中的取消
- 空模型或纯空白模型在界面映射中标为不支持，不再由通用规则生成可选思考档位
- 经典和 Agent 界面只读取并展示思考配置，取消显示界面时自动保存第一档的副作用；档位变更仍通过滑块交互保存
- 经典界面的“未选择”仅用于展示，不作为模型名参与思考规则匹配

已有请求解析继续按现有规则处理空档位、有效选择、模型切换和强制思考模型，不新增默认写入或替代配置。追加改动沿用 PR #241 与原分支。

思考档位更新属于配置服务，辅助函数放在现有 `services/core/ThinkingOptionUpdate.kt`，由同包的 `ApiConfigDelegate` 调用，测试按对应源码包放在 `src/test`。没有新增项目根级业务目录。快照审计工具只在仓库外的临时验证目录使用，不进入产品 `data/backup` 或仓库提交。

目标分支为 `dev`，工作分支为 `fix/thinking-option-crash`。公开参数和快照格式保持兼容。

## 验证

快照只改模型 DataStore 中两处无效档位；其他 4296 个条目的压缩内容和文件名保持原样，清单逐字节一致，4297 个条目 CRC 均通过。

独立使用 Kotlin 2.0.21、JVM 17 和 JUnit 4.13.2 编译实际更新协程入口及其测试，七项回归全部通过。校验覆盖不支持的档位不取消父协程、不触发服务刷新，成功时先保存后刷新，排队期间切换配置不改变保存目标，写入或刷新失败可反馈，以及保存或刷新中的取消不显示错误。

另使用实际 `ThinkingQualityMappingRegistry` 和模型列表解析对快照中的二十份模型配置进行复核，修复前两处档位无效，修复后全部满足配置校验。此核验不代表已在设备中执行快照导入。

三个变更 Kotlin 文件的 PSI 语法检查零错误；中英资源 XML、两个新资源键、严格 UTF-8 和差异空白检查通过。新提示只调用项目 `OKToast`。

完整 Android 编译、Gradle 全量测试和设备交互仍待 Debug Build / Android Tests 及实机验收。取得工作流启动信息后停止查询进度。
