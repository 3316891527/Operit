# 记忆空间入口与图谱交互设计

用户提供记忆管理、图谱总览和放大视图截图，要求先通过 HTML 重新设计入口页面及记忆图谱，再决定 Android 实现。

## 当前问题

入口把当前全局空间与空间列表分成重复区块，进入空间、重命名和更换全局的层次接近。角色跟随全局与固定空间的区别主要依赖小字，缺少清楚的使用关系。

图谱把完整标题和关系文字一起铺开，缩小时无法辨读，放大后关系线交错。当前已有手势缩放、框选、关联和文件夹导航，应保留这些能力，并增加明确的定位、回到总览与选中聚焦。

## 设计方向

- 在空间卡片内标记全局默认，明确打开记忆库和空间管理的不同操作；独立展示角色使用关系。
- 使用已有文件夹组织总览，不新增未经解释的语义分类；总览显示分组数量和联系，进入分组后查看具体记忆。
- 节点使用简短标题、类型和清楚的点击区域，正文在详情中查看。选中时优先显示相邻关系的文字，其余连接保持安静。
- 保留搜索、文件夹、框选、建立关联、新建和导入入口，提供图谱与列表两种查看方式，以及明确的缩放和归中操作。
- 提供 Android 手机尺寸的深浅主题 HTML 交互预览，使用明确标记的示例数据，不读取或修改真实记忆。

支持深浅主题，默认打开记忆管理；进入记忆库后展示按文件夹聚合的总览，点开分组查看记忆。选中时重新布置相邻节点并突出关系，详情面板保留完整正文和关系类型。支持搜索定位、列表、平移缩放、框选、新建与编辑、建立和移除关联、文本导入、空间管理及角色绑定。

所有内容与统计均为明确标记的示例数据。修改只保留在当前页面，刷新或重置后恢复；没有连接真实记忆库。搜索使用本页文字匹配，布局使用确定的示例位置，不代表 Android 检索策略、图布局性能或设备验收已完成。

本轮未改 Android 页面、数据结构和实际记忆配置。检索配置、向量索引与历史重建不在此次界面稿的展开范围，落地时需保留原入口。节点类型在本稿中为示例标签，实际实现需沿用现有标签与元数据，不另立一套记忆类型。
