# 1.13.0 累积更新日志

状态：持续维护草稿，供后续 1.13.0 发布整理使用。正文固定覆盖个人发行线从正式 `1.12.2` 到 `1.12.2+24` 的最终代码快照，不代表已经发布 1.13.0；`+24` 之后仍在推进的开放 PR 单独列在本文末尾。

这不是把几十个小修复简单堆在一起的更新日志，而是一轮跨聊天、模型、主题、记忆、语音、文件工作区、工具运行时、数据管理和发行基础设施的连续重构。正文按最终用户可感知的能力归并多轮修复，来源文档则保留每个阶段、PR、提交和发行快照，避免把大规模工程工作误读成若干互不相关的小改动。

详细依据见[来源与归并说明](sources.md)、[补丁版时间线](patches.md)和[全部 488 条提交](commits.md)。

## 版本、规模与工程阶段

`1.12.2 → 1.12.2+19` 的历史基线包含 488 条提交、4,028 个变更文件、396,249 行新增和 137,617 行删除；随后 `+20` 至 `+24` 又沿五个正式发行范围增加 232 条提交。前一组统计包含功能代码、目录迁移、删除、文档、依赖和发行文件，不能解释成净新增业务代码；合并阅读这些版本，才能看到这是一轮持续到 `versionCode 80` 的六十万行级别工程演进。

本日志采用三层记录方式：

- **正文**按最终能力描述行为，把同一功能的实现、修复、迁移和验收边界合并起来，避免把一次完整能力拆成十几个标题。
- **来源索引**按功能领域和工程阶段记录上游来源、个人仓库 PR、合并关系及未直接合入但已被后续集成的工作。
- **补丁时间线与提交附录**保留每个发行快照、版本号、源码 SHA 和 488 条提交，供追溯具体文件变化；它们是证据清单，不是功能数量清单。

- 附件成功反馈改为统一简短文案并支持点击关闭，减少重复文件名和冗长提示；修复取消请求、缺少配置与普通失败重复抛出或静默结束。

- 开发包目录排除媒体扫描，避免 TypeScript 源文件进入系统图库扫描与清理路径。

## 更新与离线资源

- 个人发行线建立固定签名、完整 APK、增量 ZIP、补丁元数据与发行摘要，签名密钥通过独立配置注入，清理发行包中的内置签名密钥库。更新器按实际已安装 APK 的哈希选择可连接到目标的补丁链，并逐步校验基础包、补丁和还原结果。
- 增量下载核对 HTTP 字节范围、响应长度和分段偏移，改善不支持分段的下载来源处理；Release 正文使用可读更新说明，机器元数据独立为附件。
- Beta 计划控制 `+n` 补丁版本的发现，关闭时只选择无加号正式版；切换渠道清理旧检查结果，退出 Beta 不将已安装版本降级。
- 应用发行统一存放于 `Operit-Kong-patch`，固定离线资源存放于 `Operit-Kong-resources`，源码仓库负责开发协作；历史应用、资源和补丁链按分仓记录迁移。
- 离线资源工作区提供本地语音模型、OCR、九种工程模板及按需下载的内置扩展，显示下载进度、速度、剩余时间和存放位置，减少 APK 中的预置大资源。
- 升级保留通过身份、文件集合、大小和哈希核验的已下载扩展，区分“已安装”与“有新版可更新”；内容未变化时不要求重复下载。
- 使用中的扩展禁用删除并提示先关闭。新版本完整校验后清理同一扩展的已知冗余版本，保留仍占用、唯一可用或来源不明的目录；中断的终端资源清理可继续完成。
