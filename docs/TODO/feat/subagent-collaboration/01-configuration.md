# 配置与模型选择

[返回计划](index.md)

模型配置的页签依次为连接、参数、上下文总结、子代理配置和功能模型。子代理提示词与模型池均为全局配置，不属于当前正在编辑的某个连接配置。

## 提示词配置

在“子代理配置”中维护名称、用途描述、独立提示词与启用状态。主代理读到名称和用途，用于决定什么时候调用这类帮手；实际子代理收到独立提示词和本次任务简报。配置标识由程序维护，无需用户输入。

提示词不固定模型。修改或删除提示词不会改写已经派发任务保存的指令快照。继续现有任务时保留该任务的提示词快照。

编辑窗口提供保存与取消。取消明确丢弃当前草稿，有修改时使用关闭按钮会先确认；页面切换通过现有保存协调器处理有效草稿，校验或保存失败时阻止离页并显示错误。

## 多选模型池

在功能模型页打开“子代理模型池”，从已有模型配置的具体型号中逐项添加。每项可启用或停用，必须填写适合的任务与能力，可以补充限制或偏好。同一配置中的同一型号不会重复添加。

建议根据实际使用填写，例如“适合长文分析和代码审阅；复杂任务优先，输出速度较慢”。不要求用户给模型编写系统提示词。模型的能力描述与提示词配置承担不同职责。

目录同时提供已经配置的上下文容量、直读图片／音频／视频开关及原生工具调用开关。这些是配置事实，并非运行基准，也不推断模型质量、价格或速度。主代理被要求依据目录选择，避免使用过时的型号知识猜测新模型能力。

初始模型池为空，提供一套“通用帮手”提示词。没有可用模型时，不能派发子代理任务，也不会自动改用主聊天模型。

## 模型引用与执行快照

模型池按配置标识和具体模型名称引用。派发与执行开始时校验池条目仍启用、配置存在、型号仍在配置中。缺失或禁用会明确报错，用户可修正配置后继续任务。

实际模型租约在一次执行内固定服务、配置和请求参数。读取配置时要求真实存在且能解码；型号按同一份配置解析，避免修改型号排序后选到另一个模型。运行中的任务使用已经取得的租约，后续配置修改在新执行时生效。自定义参数解码或类型转换失败会明确报错；共用参数读取入口也会保留这一错误，避免缺少参数继续请求。

继续任务默认仍使用原模型池条目。主代理也可以明确选择池内另一项，任务详情与每次报告记录当次的模型名称。主聊天模型的功能映射不受委派影响。

全局配置保存在独立的版本化 DataStore 中，修改按事务合并。提示词最多 32 项，模型池最多 64 项；数量和字段长度在保存时校验。
