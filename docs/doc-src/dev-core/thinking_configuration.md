# 思考规则、档位和模型连接测试

模型配置中的思考规则按列表顺序匹配提供商、模型和端点，第一条启用且匹配的规则决定行为。顺序由用户管理，不按模型名称、正则或匹配条件数量自动判断优先级。

## 从预设开始编辑

模型配置页面的“从预设添加”列出当前提供商的内置模板。可以添加一条，也可以添加全部；它们都是完整副本，追加到现有规则之后，不重置已保存的规则。每条规则的菜单提供“复制规则”和“置顶”，并保留上移、下移操作。

复制的完整副本也追加到列表末尾。需要让某条规则优先时，由用户手动置顶或上移。页面同时展示每个已配置模型命中的规则位置、档位及必须思考的约束，便于核对顺序的实际效果。

内置模板只是参数配置的起点，不代表服务端已经验证支持该参数。不同模型或网关可能接受不同字段；应用不会假定所有接口都能返回标准化思考能力列表。

## 保存和兼容

紧凑编辑器以原始规则 JSON 为基础，只更新被编辑的字段。`required`、`reasoningRequired`、`unsupported`、复合匹配、动作覆盖标记、档位中的额外动作和未知扩展字段均予以保留。原始对象外层的 `rules` 包装及元数据也保留。

修改显示的一个匹配条件不会删除其他条件。若切换条件类型会覆盖已有的另一项条件，编辑器拒绝保存并显示原因。现有匹配条件的组合语义保持不变。字符串值不会仅因打开页面或重新排序而转换为布尔值、数字。

启用的档位规则必须有非空且不重复的有效档位 ID。保存时检查动作对象、参数路径和正则表达式；无效配置不写入存储。停用的草稿允许暂时保留不完整的档位定义。没有写入动作的命名档位仍可表示使用模型默认参数。

规则保存、模型或端点切换在同一次配置事务中重新核对当前档位。一份配置仍保存一个共享档位偏好：只要它对配置中的任一模型有效就保留，不能只按模型列表第一项判断。所有模型都不再接受该偏好时，按模型列表顺序选取首个支持档位的模型，并使用该规则的第一档；均不支持档位时保存为空。直接保存档位时，非空 ID 必须属于至少一个已配置模型的生效规则。实际调用再按目标模型分别解析，功能模型已有的独立选择仍参与合法档位解析。

旧版本已经丢失的高级字段无法凭当前 JSON 可靠还原。需要恢复时使用预设添加完整副本，再由用户选择顺序及删除不需要的旧规则。原始 JSON 无法解析时，界面显示错误并阻止自动保存，避免用空列表覆盖原配置。

## 连接测试

聊天、工具、图片、音频和视频连接测试统一使用当前模型规则。存在档位时启用思考，选择配置列表第一档；开关型规则启用思考；没有规则或命中 `unsupported` 时不添加思考控制参数。这里的最低档按用户配置顺序定义，不对任意字符串或预算值进行猜测排序。

测试调用不修改已保存的聊天档位。统一解析器同时供功能调用和 Provider 使用；Responses Provider 必须传递单次请求的档位，不能忽略测试或功能调用的选择。

## 验证边界

回归用例覆盖全部内置规则的编辑保存、未知字段和复合条件、复制、字符串类型、规则顺序、失效档位、端点匹配、最低档连接测试和 Responses 单次请求覆盖。

本次本地仅执行差异、资源和引用静态检查；没有运行 Gradle、Android 构建、JVM 单元测试、设备测试或真实模型请求。参数在服务端是否受支持仍须以对应服务的实际响应为准。
