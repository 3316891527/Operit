# 文件链接入口与主题前景色

文件页此前只给根容器绘制背景，撤销、重做、搜索、新建等按钮仍读取外层的 LocalContentColor，容易在深色或自定义主题中与背景接近。WorkspaceManager 和 FileBrowser 的根 Surface 现在同时提供不透明 surface 与 onSurface，顶部标签 Surface 单独提供 surfaceVariant 与 onSurfaceVariant。

## 聊天文件入口

新增 `ui/features/chat/webview/workspace/links/` 功能目录。WorkspaceFileLink 解析路径、来源环境与行号，WorkspaceFileLinkHost 作为 ChatScreenContent 的文件入口容器；Cursor 与 Bubble 共用的 LinkPreviewDialog 在点击“访问”后把文件请求交给该容器。

| 链接形式 | 来源与打开行为 |
| --- | --- |
| `/sdcard/...`、`/storage/...`、`file:///sdcard/...` | Android 设备文件 |
| `/home/...`、`/tmp/...`、`linux:///path`、`file://linux/path` | Linux 文件 |
| `android:///path` | 显式 Android 来源 |
| `repo://名称/path`、`repo:名称:/path` | 指定附加仓库 |
| `?environment=linux` 等显式来源 | 使用指定来源，不根据路径再次切换环境 |
| `#L12`、`:12`、`?line=12` | 从路径分离一基行号，在编辑器初次打开时定位 |
| HTTP、HTTPS 和其他应用协议 | 沿用原外部链接入口 |

解析后使用对应环境的 file_exists 判断文件或目录，再按已有文件类型进入查看器。目录使用 FileBrowser；文本使用 read_file_full 和已有 CodeEditor；图片、音视频、PDF、Word、Excel 使用既有直接预览。ZIP 等格式显示路径、大小、打开方式和分享，可进入父目录；打开或分享实际文件继续使用已有缓存与 FileProvider URI。

文件链接窗口不会绑定或替换当前聊天的工作区。关闭编辑文件复用原保存、放弃、取消流程；只有关闭完成后才返回聊天或此前打开的目录。窗口的系统返回不直接销毁编辑内容。后台读取保留取消语义，并展示实际来源的错误。

## 回归范围

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| 1 | 在浅色、深色及背景图主题打开文件，检查编辑和浏览工具栏 | 图标跟随文件页主题，前景清晰，底色不透明 |
| 2 | 点击聊天中的设备 `.md`、`.txt` 文件链接 | 在应用内显示真实文本；保存写回设备文件 |
| 3 | 点击 `/tmp/...` 和显式 `linux:///...` 文本链接 | 在应用内读取 Linux 文件；保存写回 Linux |
| 4 | 点击附加仓库中的文件与目录链接 | 保留指定仓库来源，进入相应查看页或浏览器 |
| 5 | 点击中文、带空格、百分号编码及行号的链接 | 文件路径正确，支持的行号只在打开时定位一次 |
| 6 | 点击设备和 Linux 的 ZIP 链接，再分享或进入父目录 | 显示文件信息；分享真实文件，目录来源正确 |
| 7 | 从链接进入图片、音视频、PDF、Word、Excel 预览 | 复用既有类型预览，关闭返回聊天 |
| 8 | 修改文本后顶部返回和系统返回，分别选择保存、不保存、取消 | 复用未保存确认，取消后保留编辑内容 |
| 9 | 点击目录链接，浏览子目录、打开文件，再关闭 | 返回之前的浏览位置；不改变聊天绑定 |
| 10 | 点击网页链接、缺失文件或不可读文件 | 网页保留原行为；文件显示对应错误，页面可以返回 |
