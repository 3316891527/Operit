## 真实日志审计方法

样本取自已完成的 [Debug Build #291](https://github.com/3316891527/Operit/actions/runs/45033821311)。只去除 GitHub Actions 的时间戳和运行脚本前导，保留 Gradle 命令输出。分别检查完整命令输出、最后约 16000 字符的连续尾部，以及原日志中最长的连续完整任务行片段。尾部和任务片段是明确标注的连续摘录，不能代表整个构建。

通过生产展示投影和聊天格式化器计算前后消息字符数，计入原文路径、临时文件说明、JSON 转义、XML 包装和既有消息上限。压缩样本均逐字检查 UTF-8 归档与输入一致。测试目录和实际设备目录长度可能不同，收益记录保留对应的完整测量口径。

- 完整构建输出约 40 万字符，超过 256000 字符输入上限，跳过精简，已有 64000 字符消息截断策略继续生效
- 约 1.58 万字符的真实构建尾部包含诊断，原生和包 JSON 两种展示均未精简，字符收益为 0
- 7118 字符的真实连续任务行片段，在原生和包 JSON 两种展示中均减少约 91% 的消息字符，原文归档一致
- 受控失败样本在成功进度之后加入编译错误与堆栈，诊断逐字保留，消息字符减少约 85%
- 诊断位于进度之前的受控样本整体保留，字符收益为 0

这些数据说明连续成功进度可以显著减少上下文字符，不表示整体 token、调用费用、每条终端命令或完整构建都有相同比例的收益。长输出已经返回文件入口时直接保留入口，不展开文件来追求压缩率。
