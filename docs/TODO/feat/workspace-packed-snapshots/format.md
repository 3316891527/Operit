# 快照分卷 v2 的格式与生命周期

本轮只替换内容对象的存放方式。操作记录、工作区观察和终端基线仍保存原有 SHA-256 哈希，文件路径、对话归属、记录 ID 与消息协议不变。存储元数据继续位于 `workspace_changes/v1`，对象卷使用独立的 v2 格式。

```text
workspace_changes/v1/
	objects/
		<uuid>.pack
		<sha256>             尚未迁移的旧对象
	objects-v2.sqlite
	objects-v2.sqlite-wal   SQLite 打开期间可能存在
	objects-v2.sqlite-shm   SQLite 打开期间可能存在
	operations/
	observations/
	terminal-observations/
```

位置索引放在 objects 目录外，用户直接删除该目录或其中的卷文件时，不会删除仍打开的 SQLite 数据库。缺失卷表示内容已清理，只影响其中的对象。后续写入使用新的 UUID 文件名，不复用旧卷标识。只有尚未被索引的 v1 哈希文件属于待迁移内容；已经清理或损坏的 v2 内容不会从残留旧副本重新读出。

## 卷与记录

所有整数使用大端序。卷头为 16 字节，依次保存 4 字节 `OPK2` 魔数、4 字节版本 2 和 8 字节保留值 0。每条对象记录包含 4 字节 `BLOB` 魔数、4 字节内容长度、32 字节 SHA-256 摘要和原始内容字节。摘要既是全局身份，也是内容完整性校验。

常规卷目标为 1,048,576 字节，包括卷头与记录头。一条记录不会跨卷：追加后超过目标时，先封存旧卷，再创建新卷。单对象大于常规卷容量时独立成卷；最大内容仍为原有 2 MiB。空内容和二进制内容都可存放。

SQLite 使用 `user_version=2`，未知版本拒绝打开。`snapshot_objects` 保存哈希、卷名、记录偏移、长度和有效状态；`snapshot_volumes` 保存卷的已提交边界、已删除字节和封存状态。读取与遍历按页进行，每页最多 64 个位置，内存位置缓存最多 256 项，不缓存全部对象内容。

## 写入与恢复

写入在单个存储实例内串行执行。相同内容共享同一个哈希和对象，不会重复追加。当前写卷保留一个打开的文件句柄，减少重复打开文件；重复对象优先命中固定容量的位置缓存，并继续检查卷是否仍存在。

发布顺序如下：

1. 在新卷写入头部和首个完整对象，或向已有卷追加完整对象记录
2. 同步卷内容；新卷再同步目录项
3. 在 SQLite 事务内一并发布新卷或更新边界和对象位置，位置库使用 FULL 同步
4. 成功后更新内存中的写入边界和位置缓存

写入或索引提交异常时关闭当前写句柄，下一次恢复依据磁盘索引决定边界。恢复会移除未被索引引用的卷，截断已提交边界之后的尾部；已提交区域截短、头部版本错误或摘要不匹配会报告损坏，不伪装成空文件或内容已清理。卷文件不存在则使用已清理状态。

应用只有一个 WorkspaceChangeStore 实例。该实现不支持多个进程同时写入同一个对象目录，不能让独立修复工具在应用运行时直接修改索引或卷内容。

## 旧对象迁移

首次使用在 IO 协程中逐个迁移旧哈希文件，不枚举并保留全量路径列表。每处理 64 个对象让出执行机会。单个对象先验证旧摘要，追加并提交新位置，再从新位置读回校验，成功后才删除原文件。中断前未提交的对象保留原文件；已提交但尚未删除旧副本的对象，恢复后核对新位置即可继续清理副本。

读取使用明确的版本归属：位置索引中没有该哈希时才读取尚未迁移的旧文件。记录已清理的哈希保留墓碑，避免旧副本在部分迁移和外部清理后重新出现。迁移失败会记录诊断并保留尚未迁移的源文件，不清空操作历史。

新包实际运行时才会执行此迁移。本轮开发和验证只使用临时目录，没有迁移或清理设备中的真实历史。

仅识别 v1 独立哈希文件的旧版 APK 不能直接读取 v2 卷。迁移完成后安装这样的旧包，已迁移历史的内容将不可阅览；格式升级没有改变原有哈希，但旧版读取器没有卷位置解析能力。

## 删除与空间回收

沿用原有引用检查：操作记录、其他对话、工作区基线和终端基线都不再引用候选哈希后，才允许标记对象删除。正在采集的快照继续受既有操作互斥锁和终端扫描引用保护。

删除先更新有效状态和卷内废弃字节，随后后台进行有限压缩。只有已经封存、废弃内容至少达到一半的卷进入压缩；一轮最多处理约 4 MiB 的旧卷字节。仍有效的内容逐对象复制并校验，替代卷同步落盘后通过事务切换位置，再删除原卷。取消或事务失败保留原来已提交的位置。整卷都不再使用时直接删除，不创建空替代卷。

没有达到阈值或单轮预算之外的空隙继续保留，后续删除操作可再次触发压缩。这个实现减少小文件数量，但不提供历史总容量配额，也不改变保留时长。索引墓碑、SQLite 页和未达到阈值的卷内空隙仍占空间。

## Android 目录同步公开 API 修正

首次 Android CI 在 AndroidTerminalIndexDatabase 的目录打开标志处报告 O_DIRECTORY 未解析。该常量没有暴露在公开 Android SDK 中，上轮本地平台替身错误地提供了它，不能作为公开 API 兼容证据。

修正采用 O_RDONLY 打开目录，通过同一句柄的 fstat 与 S_ISDIR 确认目标类型，再执行 fsync，并在 finally 中关闭句柄。仍然要求目录同步成功，不省略持久化步骤。本地使用真实 Android 35 SDK 中的 14 个公开 android.system 类复现旧引用失败，并确认修正后适配器编译通过，不再提供 OsConstants 替身。完整 Android 编译继续由修正提交上的 assembleDebug 和 Android Tests 工作流验证，启动链接登记在 PR #253。
