# 新建对话入场动画请求生命周期修复

## 问题与证据

新建对话后删除该对话并退到后台，曾连续出现崩溃。截图中的 `IllegalArgumentException: Required value was null` 指向 `NewChatIntro.kt` 中生成粒子轨迹时对可空 `requestId` 的强制非空检查。

动画是否绘制由本地 `playing` 状态决定，而请求 ID 来自独立的状态流。请求清空与协程取消的收尾不是同一状态更新；绘制子组合可能仍持有可空请求参数，导致动画请求失效时发生崩溃。

设备进程退出历史确认 2026-11-14 23:35:51、23:36:41、23:37:27 三次主进程以 `EXIT_SELF / status=1` 结束，与全局异常处理器的退出方式一致。抓取时主日志和事件日志已覆盖对应时间段；这些退出记录不包含异常堆栈，不能单凭记录认定三次均为同一异常。

## 目标与范围

- 每轮动画只使用已确认非空、固定的请求 ID
- 请求清空时移除整轮动画组件，请求替换时重新创建动画状态
- 旧动画的取消、离页和完成回调只消费旧请求
- 保留现有播放条件、1.8 秒动画、5 秒请求过期和无动画设置行为

本次修改覆盖入场动画组件及其 Compose 设备回归源码，复用现有测试宿主依赖；不调整会话存储或删除规则。
