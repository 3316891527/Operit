# 图片加载失败的可检查详情

用户对比同一分组的直接 Markdown 图片和 emotion 标签：两处提示加载失败，一处无说明文字的图片成功。不能用图片是否带说明文字判断消息来源，普通 Markdown 的 alt 也允许为空。

核对测试应用原始回复后确认，两处失败实际都是模型直接输出的空 alt Markdown，引用了不存在的素材文件；成功的常规 Markdown 引用了另一张现存图片，最后成功的回复才包含合法 emotion 指令。详细设备证据保存在本地诊断目录，仓库不记录实际设备路径。

本轮先核对测试应用的原始回复、分组文件和 emotion 转换，再把真实加载错误、资源位置与图片 Markdown 做成可检查详情，并在错误回调记录日志。图片尺寸、对齐和成功外观沿用当前实现；不对无效文件路径猜测替代图片，不重写历史消息。

内联图片失败时默认显示简短提示和展开箭头，点击后在图片高度约束外显示实际异常类型、消息与原因链、解析后的资源位置、原始图片 Markdown。详情支持文本选择复制，也适用于禁用弹窗的浮窗。HTTP 查询内容在详情和日志中隐去；Coil 错误回调对同一请求的相同错误去重记录。

emotion 素材仅在本轮真实新选图时记录 `source=emotion`、分类与资源，流式快照重算复用原选择而不重复记录。不通过空 alt 推断来源，不修改成功图片布局和全屏预览，不为不存在的文件选择替代图片。

新增五项诊断格式回归源码，覆盖缺失文件及空 alt、相对资源与原文区分、无消息异常、HTTP 查询脱敏、转义 Markdown 和非 HTTP 资源；另新增一项 emotion 选图诊断回归，覆盖快照复用、第二次选图与未知分类。本地只做静态检查，不编译或运行测试；提交后发起 Debug `assembleDebug` 与 Android Tests，登记后停止查询。展开、复制和日志的实际设备行为仍需新 APK 验收。

图片问题交付后继续调查 GitHub 包的终端会话、命令等待和结果返回链路，不将 #277 的取消修补视为已解决初始等待问题。
