# 日志接入和引用清理

TerminalFileJournal 的状态只持有磁盘索引和观察器，不再持有、复制或异步序列化完整基线。通知队列也落盘，每次采集取固定大小的批次；目录事件跨批次读取子路径的明确来源，保留 executionId 和 subagentExecutionId 的归属。

旧 JSON 逐项读入暂存代次，数据及完成标记在同一个事务提交后再删除源清单。迁移失败保留源文件并报告错误。关闭日志先取消并等待任务退出，再注销目录监听和释放索引连接。

删除指定历史记录时，仅查询候选哈希是否仍被正式基线、扫描代次、在途内容租约、未迁移清单或其他操作记录引用，不再为垃圾回收加载整份终端基线。历史按文件依次过滤，避免为指定会话先构造所有会话的记录列表。

[DONE] 代码接入、资源释放及引用保护已实现。

运行数据清理仍是单独的维护步骤。设备上的旧版进程仍持有基线，删除磁盘 JSON 不会解除其内存引用；必须先让新实现接管并协调在途扫描，再清理用户指定的旧基线和其独占对象。只读磁盘审计不等于已执行删除，不得清空源码、聊天数据库或仍被历史引用的内容。
