# 调用参数与拦截提前结束

PR：#227，分支 `fix/visit-web-timeouts-errors`

用户要求将网页访问的超时和内容等待交给每次工具调用控制，删除“显示与行为 / 自动化”中的网页访问等待设置及其偏好代码。当前的 10 秒加载、3 秒提取、30 秒整次访问上限和最多 10 秒懒加载等待需要改为调用参数；旧参数和成功结果结构继续支持。

参数方案：

- `timeout_seconds`：整次访问期限，包含并发排队，默认 30 秒
- `load_timeout_seconds`：可选的加载阶段期限，未指定时使用整次访问期限；重定向不重新计时
- `read_timeout_seconds`：可选的脚本读取期限，未指定时使用整次访问期限
- `wait_seconds`：页面完成后等待懒加载内容的时间，默认 0；提前提取可以跳过这段等待

秒数使用整型，超时必须大于 0，等待可以为 0。没有业务层固定最大值，不静默截断参数；仅检查数值能否安全转换为毫秒及组合是否合法。仅增大整次期限即可延长未单独指定的阶段，避免隐藏的固定加载或读取上限。

拦截处理：

- 主页面明确网络错误、HTTP 错误、证书错误仍立即失败
- 在可用的 HTTP 错误响应头中识别 Cloudflare 的 `cf-mitigated: challenge`，返回专门的 Cloudflare 错误
- 页面首次可见后检查页面结构，并在加载和等待期间持续检查；识别出 Cloudflare 挑战、拒绝页或明确的访问策略拦截页时立即结束，不等待页面加载完成或倒计时
- 页面提取前再次检查，覆盖返回 HTTP 200 的拦截页
- 不因网站使用 Cloudflare、包含 Turnstile 控件、正文提到防火墙或加载缓慢而判定被拦截
- 没有响应或明确证据时保留网络与超时错误；不推断用户是否配置代理，不执行验证绕过或额外预检请求

Cloudflare 响应标记依据：[官方文档](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/)。

实现范围包括访问会话、参数验证、页面检查、工具中英文参数、设置状态与偏好清理、相关资源和回归。验证覆盖延长时限、非法参数、重定向、取消、加载中及等待中拦截、HTTP 200 挑战、普通 Cloudflare 网站与文章的误判防护。
