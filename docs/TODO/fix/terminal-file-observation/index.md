# 终端文件变化采集与来源

## 问题与结果

文件工具直接保存操作前后快照；原有终端文件观察依赖工作区绑定。未绑定工作区时，终端中的 Python 等程序创建或修改文件不会进入对话历史。文件通知晚于执行作用域结束时，还可能丢失已知工具来源。

本次在应用共享终端接口接入文件事件日志，按本地 Linux 根文件系统和可访问的映射挂载建立观察范围。文件采集不依赖工作区绑定，不解析命令内容，也不为 `super_admin`、GitHub 包或其他插件分别添加判断。

## 实现

- `TerminalObservationRoots` 复用固定终端子模块中的 PRoot 挂载定义，按物理目录去重，为 Linux 根和挂载源保留代表路径
- `TerminalObservedFiles` 建立修改前基线，根据事件增量重读子树；文件最大快照 2 MiB，每轮每个观察根的读取预算为 64 MiB，预算不足明确保留不可用状态
- `TerminalFileJournal` 统一管理目录观察、活跃执行、交互输入、快照持久化及错误。命令结束后在后台通过 Android FileObserver 的共享事件队列收集先前通知，再读取最终内容
- 应用 `Terminal` 的普通、流式、托管及隐藏执行统一关联来源；托管执行在创建 Flow 前恢复原始上下文。交互输入保留提供的调用者，独立调用标为 `terminal`
- 记录分别保存完整调用名称、执行编号和 `terminal` 类别；并发执行无法唯一判断时仍使用终端类别。文件系统监听是采集方式，不作为已知终端记录的调用者名称
- 文件工具继续直接记录，并同步推进相应观察基线，避免同一次写入重复入账。长任务分批更新保留最早的 before 和最新的 after，清除进行中记录不会使旧记录复活
- 目录观察不跟随软链接递归，链接内容只保存目标文本。采集排除虚拟文件系统、Git 元数据、自身存储、缓存、数据库及应用日志；销毁时停止观察器和事件屏障
- 新模型字段提供默认值，旧操作记录可继续读取。清理历史时保留持久化基线及活跃基线仍需引用的内容对象

## 范围与限制

观察范围是本地终端中应用可访问的真实文件目录，包含 Linux 根文件系统和可访问的挂载源。SSH 远端文件、绕过应用 `Terminal` 的内置终端 UI 直连、虚拟文件系统及已排除的应用内部目录不由这条新增链路采集。

首次使用需要枚举目录并建立基线，成本随目录规模增长。读取预算只约束内容字节数，不约束目录或观察器数量；操作系统观察器上限、事件溢出及离线不可读范围仍可能影响覆盖。超过快照上限的文件可以保留变化信息，但没有完整文本差异；文件通知之间发生后又被撤销的短暂写入不会逐次留档。

FileObserver 不提供可靠的写入进程身份。并发写入只能依据活跃终端执行关联来源，不能保证排除同时发生的外部写入；跨对话同时执行时，来源归为全局终端记录，不任意选择某个对话。空闲且无交互归属的事件只推进基线，脱离已完成命令继续运行的子进程不保证进入原执行记录。托管任务在实际执行结束前持续保留来源。

本分支以 PR #222 的远端提交 `4c45381649ab961b3aae05d6675d432bb41a0bde` 为分支基线，完整保留其操作面板、汇总、Diff 加载、展开状态和工作区采集。PR #224 的目标分支为 #222 的 `fix/workspace-import-performance`，审核时只显示本次增量；构建使用 #224 的完整分支，产物同时包含 #222 和本次终端修复。

绑定目录中的变化继续由 #222 的观察器发现。通知会保存共享终端是否已接管该路径的信息，终端负责的写入只推进工作区基线，终端保存后再确认相同快照，避免执行结束后的旧通知产生重复记录或 `filesystem` 标签。没有经过终端的工作区变化仍保留原有采集行为。统计计算继续遵守 #222 的自动加载阈值。

## 小文件与真机超时回归

普通本地命令从实际提交到退出计时。观察基线使用一次目录遍历建立订阅并采集快照。命令结束时核对当前对话已记录的本地文件内容，使用文件通知相同的基线和保存流程写入变化。外层主动取消仍会停止任务。历史差异先展示行内容，语法高亮随后更新。核对已有记录仅用于本次执行，无法还原此前遗漏的终端历史。

设备回归 `TerminalFileJournalAndroidTest.mappedEditOfTrackedFileIsSavedOnCommandExit` 在打开映射写入的文件描述符期间结束执行，检查操作数量、调用者、原文与最终内容。人工验收可在未绑定目录中为 `message.txt` 建立两行初值，用 Python 修改第二行并追加第三行，核对创建记录、终端修改和三行汇总，再切换至 Markdown 查看行差异。

本轮 24 项集成检查和 55 项 JVM 回归均通过。测试专门屏蔽了目标文件的全部通知，验证 Python 写入后记录与汇总都显示最终内容。Android 设备用例和界面首屏耗时待真机验收。

## 从 Operit2 复核终端与变更记录

Operit2 的 `change_review/src/model.ts` 从显式 `fileDiff` 结果整理消息变更，`git.ts` 通过 Git 工作树读取终端写入。`VisualFileSystem::isWithin` 先解析挂载身份再比较路径。Operit 的共享存储记录也使用这个路径比较原则，Android `/sdcard` 与映射到同一共享存储的 Ubuntu 路径进入同一文件历史。

插件文件工具原来已经绑定发起对话。现在 `Tools.System.terminal` 也使用当前脚本的 `toolCall`，普通、流式、托管、隐藏和交互调用都保留真实来源。文件比较继续使用已有的前后快照，已记录的文件在命令起止按挂载路径读取实际内容。只有一条操作时，选择汇总同样显示汇总标题。

设备验收使用未绑定工作区的对话。先用 `create_file` 写入 `/sdcard/Download/operit-shell-test/create-file-demo.txt`，再通过 Ubuntu 修改同一文件。变更列表应只有一项，操作菜单同时显示 `create_file` 和终端工具名，汇总显示终端写入后的内容。

本轮通过 25 项本地集成检查和 55 项 JVM 回归。新增的共享存储用例屏蔽目标文件通知，并保留原长度和修改时间，核对终端写入与文件工具创建历史合并。另在 Node.js 中运行实际生成的脚本桥和内置 `super_admin.js`，以替身接收原生调用，核对并行调用、流式执行和托管输入携带各自的调用编号。共享存储分组及单条记录切换汇总的 Android 设备用例待运行。

## 冷启动终端耗时

Android 真机日志中，终端会话初始化用了 4.5 秒，会话就绪后到用户取消又过了 17.3 秒。对应设备的 `/sdcard` 基线有 77176 个文件条目，磁盘清单约 17 MiB。直接在该应用的 Ubuntu 根下执行 `pwd`，连同 PRoot 启动约 0.50 秒。

首次使用本地终端时启动文件观察。挂载根的递归观察、快照初始化和基线落盘在后台执行。提交前最多等待 50 毫秒，期间尝试监听根目录、常用目录和已知会话工作目录，并核对当前对话已记录的文件。命令退出后，结果可以先返回，文件通知和最终快照由后台收集。后台初始化期间，已监听路径下的创建事件可以入账，已核对的路径覆盖后台扫描结果，包括已经删除的文件。尚未监听的目录或未及时完成命令前核对的文件可能漏记，缺少可靠原文时标记原快照不可用。

普通命令日志分别记录观察准备开始、命令提交、终端执行阶段完成和观察收尾。快速连续执行涉及同一文件的命令时，异步收尾可能合并中间状态。

设备用例 `coldExecutionCapturesNewSubtreeWhileBaselinePreparationIsBlocked` 让后台准备无法开始，核对命令仍可进入执行并在收尾时记录新建子树。`commandPathDoesNotWaitForLockedHistoryStore` 覆盖文件记录锁被占用时的命令路径。待运行设备用例，并在同一 Debug 环境使用大量测试文件，分别测量冷、热会话的 `pwd` 工具耗时，核对共享存储和 Ubuntu 写入的前后快照。

## 受限共享存储路径过滤

反馈截图中的观察失败来自 Ubuntu 根内的 `sdcard`、`storage/emulated/0` 挂载占位目录，以及共享存储的 `Android/data`。终端日志现在直接排除这些子树。挂载占位路径按 Ubuntu 根下的词法路径匹配，不解析末段链接；真实共享存储仍由挂载源独立观察，普通工作目录和下载目录继续记录变化。

目录无法读取时，文件树遍历可能在进入目录回调之前失败。失败回调同样检查排除规则，已排除路径不再写入不可读清单。其他路径的读取错误继续保留原有提示，历史记录格式不变。

验证：`git diff --check` 和三个变更文件的 UTF-8 检查通过。完整 Android 编译与 JVM 回归交给本分支的 Debug Build 和 Android Tests 工作流，结果以运行页为准。真机需在原场景重新打开终端并执行普通文件写入，核对不再出现上述路径的红色提示，同时正常生成变更记录。
