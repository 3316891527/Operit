# Token 统计运行质量、计价与配置显示修补

维护者在 +31 页面反馈命中率与成功率缺少状态颜色，运行质量始终显示占位，Token 显示单位来回切换失效，以及中转倍率、金额精度、公式和配置可见性需要改进。直接依据随消息附带截图分析，不读取附件路径。

## 作用域

1. 命中率按 90% 与 50% 分级，成功率按 95% 与 70% 分级；缺失值使用中性色，明暗主题均可读
2. 将平均首字延迟、P95 完整耗时、已定价请求均费与成功请求 TPS 接到真实数据；请求明细增加 TPS，缺失时不猜造
3. 修复百万、十亿 Token 显示单位切换往返；持久单价保持每百万，不受展示单位影响
4. 新增默认 1 的计费倍率，贯通价格草稿、持久设置、解析、按 Token/按次计价与费用构成；旧设置默认保持原值
5. 金额展示改为八位小数，公式显示单位、币种与实际生效的倍率；峰谷和长上下文规则未开启或倍率为 1 时省略对应因子
6. 配置列表默认排除未关联及已经隐藏的配置，计数与列表一致；保留历史请求及既有用量、费用

## 费用对账证据

截图中的请求为未缓存输入 3229、缓存读取 173312、输出 925。应用展示当前单价为 0.2、0.02、1 每百万，得到 0.00503704。服务端展示 2、0.1、10 每百万并乘 0.1，得到 0.00330392。数字差 0.00173312 正好来自缓存单价 0.02 与 0.01 的差别；两页还分别标为 CNY 与 USD，不能视为同币种最终扣费相等。核对实现后说明，不能把差额归因于四位显示舍入，不能擅自改写用户真实配置。

## 分工与验证

计价后端与质量汇总分别独立实现，主代理处理价格编辑、公式、单位状态、明细、配置过滤、资源和集成。所有新增注释使用中文 UTF-8，维护已有存储兼容，不增加未经要求的兜底。

补充必要的阈值、质量口径、倍率往返、单位往返和配置可见性回归源码。设备不执行 Android 构建或 JVM 测试；完成静态语法、差异、仓库卫生、本地化和文档链接检查后，推送开发 PR 并发起 assembleDebug 与 Android Tests。登记启动后不轮询；远端通过与实机验收结果另行记录。


## 实现与交付边界

原运行质量界面写死破折号，现接入完整筛选范围的独立有效样本，没有样本数门槛。详见[运行质量与比率口径](01-runtime-quality.md)。TPS 同时接入总览、请求列表和明细，未知时不以整次耗时猜生成速度。

统一倍率使用 billingMultiplier，默认 1，允许有限非负值。按 Token 或按次计费都只在本币分项合计后乘一次，随后再换算币种。配置价格行的明确 1 覆盖模型倍率；删除该配置价格设置后沿用现有模型价格解析。Room 手动迁移 31→32 增加默认 1.0 的列，原单价、用量、旧偏好导入与整库备份保持原有语义。

金额显示保留八位小数，只在展示环节舍入；编辑价格使用原始十进制字符串，避免打开后保存把小额单价舍入为零。费用构成和公式仍引用同一计价器，峰谷、长上下文和统一倍率为 1 时省略因子；只有实际触发的非一倍率展示，币种不同时才显示汇率。

总览原先自行选择 K/M/B，绕过用户设置。现在总览、趋势与列表共用所选 Token 单位。首载偏好完成前不可打开设置，保存期间防止重复提交和旧草稿重开；纯展示单位切换直接重组，不重新查询统计或换算单价。

配置页、模型展开、总览及标签计数共用 ID 非空、仍存续且未隐藏的配置视图。筛选选项按可见配置 ID 去重；默认不把筛选改成现存 ID 集合，因此历史请求与费用总量保留。

已新增 26 项回归源码，其中 20 项 JVM、6 项 Android，并更新 7 项既有回归。覆盖截图对账、统一倍率只乘一次、原币金额、重置和迁移、精确 P95 与取消清理、比率阈值、TPS 有效样本、单位往返与配置可见性。30 个 Kotlin 文件通过 PSI 语法解析，11 份 XML 解析通过，UTF-8、资源引用和差异空白已核对。尚未运行项目编译、JVM、Room、SQLite 或 Compose 设备测试；远端构建和测试启动后另行登记，不把静态检查视为运行通过。
