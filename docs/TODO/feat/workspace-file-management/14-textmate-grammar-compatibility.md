## 规则修复

XML 的 ASP 注释将 `end` 与 `name` 错误放在 `captures` 中。引擎把这两个字符串当作规则对象，导致 XML 及其嵌入使用者编译失败。将这两个属性移回注释规则，保留第 0 组的边界着色，并检查注释结束后恢复标签和字符串颜色。

Racket 的 `lambda-onearg` 直接使用规则数组，改为显式 `patterns` 规则。十二处捕获名称字符串和八处单项捕获列表改为规则对象，保留原有名称、组号和表达式。Stata 的 format 捕获名称同样改为带 `name` 的对象。Wikitext 的两处空捕获改为空规则对象，保留组号和周围捕获。

新增结构检查发现 Jinja 的十二处 `captures`、`beginCaptures`、`endCaptures` 是数组。按数组下标生成数字捕获字典，第 0 项对应整个匹配，保留分隔符着色；避免进入引擎不能正确处理的数组转换路径。以上五个资源均保留 `upstreamSha256`、当前 `sha256` 与 `localChanges`；已有 Kotlin 嵌套注释修正继续保留。

JSX 与 TSX 的大写组件 `Button` 使用类型作用域，普通小写 HTML 标签使用标签作用域。回归同时检查类型、标签、字符串与数字，保留主题映射原有语义。

## 资源管理选择

TextMate 引擎使用固定 Maven 依赖，本地保留 UTF-16 和动态终点引用兼容修正；后续 Markdown 删除线调整与失败报告见[自定义高亮说明](../../../doc-src/dev-core/editor-highlighting/editor-highlighting.md)。约三十八万行增量主要来自语法 JSON、来源和许可证数据，不等于新增同等规模的应用逻辑。已核对整套 assets 约 12.2 MiB，模拟 ZIP 压缩约 1.62 MiB；这些数据不能当作 APK 增量测量。

本轮保留 242 个语言定义、18 个注入规则和原有文件关联，不引入构建时语法下载。资源入库便于离线构建、复现旧版本、审阅本地修正；代价是 Git 中实际保留这批第三方数据。构建时下载固定且校验的资源包可以减少当前源码树，代价是新增生成流程与首次下载要求；相同规则最终仍需进入 APK，不会自然减少包体和运行开销。现有提交已进入 Git 历史，后续删除资源也不会自动消除历史对象体积。

`.gitattributes` 将语法 JSON 和上游 NOTICE 标为第三方生成数据，并标记生成的 Kotlin 文件识别目录。GitHub 可折叠这些差异，许可证可排除在自有代码统计之外；来源清单 `catalog.json`、应用适配和回归源码正常审阅。这些标记不删除资源、不减小实际 Git 体积，也不承诺消除 PR 原始新增行数。
