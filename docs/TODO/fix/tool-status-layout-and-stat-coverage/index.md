# 工具过程统一汇总与统计样本覆盖

## 背景与目标

已发布版本的普通回复同时包含总用时折叠标题与内部工具组折叠，单项工具又另起一行显示状态。首轮修复把状态移入工具行，但仍会占用参数预览的空间。根据实际试用反馈，工具行应恢复为工具名和参数，耗时、执行状态、思考次数及调用次数统一显示在第一个过程节点上方的一条折叠标题中。

工具过程只保留一个汇总入口。后续工具批次和思考继续累计到同一标题，展开后显示原有工具、结果与中间说明，最终正文保持在汇总区域外。统计总览继续使用明确可计算的样本显示比例及数据覆盖。

## 实施范围

- 普通聊天时间线与完整文档、悬浮窗共用工具过程范围。范围使用原节点索引和首节点稳定标识，后续批次追加时不产生新的组标题，不叠加整条回复的过程折叠入口。
- 组内工具、结果、中间说明及原生卡片保持原渲染入口、XML 子流与详情状态。最终工具之后的正文常驻，展开、收起均不隐藏最终答案。
- 累计耗时放在汇总标题前部，执行状态、思考次数和调用次数跟随其后。单项工具不再显示状态与耗时，工具名称之后直接预览参数，保留详情弹窗及结果成功、失败标识。
- 工具计时继续订阅现有运行态，串行区间累计、并行重叠区间只计一次；结束后固定耗时。没有历史计时记录时不伪造耗时，不改变持久化协议。
- Waifu 继续使用专用过程入口，工具耗时统一展示在过程标题，不在单项工具卡片重复显示。
- 成功率为成功次数除以状态明确的请求数。正常结束但未确认成功的 `COMPLETED` 只进入分母；历史空状态和不识别状态单独显示为未知。
- 缓存率仅汇总同一批输入拆分完整、非负的成功用量事实，使用缓存读取 Token 除以这些样本的全部输入 Token。完整历史事实沿用既有规范化；失败、取消及未确认用量的诊断数据不混入分母。卡片说明完整与不可用的请求数。

## 兼容性

保持既有消息、工具执行计时、工具参数、折叠设置和数据库格式，不回写历史记录。工具过程使用独立稳定键，不读取旧的内部小组收起选择。纯思考保留原有回复过程入口；只读、全部及完全折叠继续决定工具过程的默认展开状态。

新增统计汇总字段有默认空值；没有覆盖数据时明确不显示缓存比例，不从不同样本的字段总和拼出比例。保留零命中与无有效输入的区别。

本次不修改应用版本号，不改写已经发布的 2.0.0 更新日志；修复通过独立 PR 交付。

## 验证安排

回归源码覆盖单个工具、多工具、多轮批次的统一标题、计数累计、稳定标识、展开和收起、最终答案常驻、中间说明及卡片保留、参数详情点击、静态正文时计时更新，以及未知历史、互补缺失输入、失败取消、零命中、完整筛选范围与分页隔离。

静态检查、独立复核及远端工作流的启动信息在交付回执记录。设备回归源码与 JVM 回归源码分别保留，不将静态检查或设备测试编译等同于实际设备执行。
