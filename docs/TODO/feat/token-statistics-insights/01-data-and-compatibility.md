# 数据与已发布版本兼容

原 token_usage_records 保持成功用量事实，已有价格、缓存写入归一化、峰谷和长上下文计费器继续作为金额真值。数据库 30→31 增加 requestId 唯一可空索引、token_request_logs 和 token_stats_recording_state，不反推历史状态、来源或耗时。

请求结束时写日志，并与成功 fact 同事务关联。SUCCESS、FAILED、CANCELLED、COMPLETED 表示确实观测到的结束结果；COMPLETED 表示传输结束而成功未确认。日志没有正文、提示词或错误原文。首段文本耗时是装饰器观察到首个非空文本的单调时钟间隔，不等同 HTTP 首字节耗时。attempt 仅为实际回调编号。进程被杀时没有结束回调的在途请求不会补造日志。

清空事务同时清除两类用量并递增持久 epoch，价格与导入完成标记保留。清空前获取的 epoch 无法在清空后写入。测试只能使用隔离内存数据库和临时 DataStore。

旧累计导入没有逐次身份，仅进入汇总；旧单次 fact 可以查看用量，未知字段留空。日志与 fact 关联去重。失败、取消或未确认的诊断用量不加入成功累计，费用为未知。输入分项冲突时不补造分类，费用归入输入明细未分配。

请求时间/耗时排序由 SQL 直接分页。费用、Token 排序与峰谷过滤逐行按真实规则写临时排序表，再 SQL LIMIT/OFFSET，仅保留当前行和当页。导出在同一数据库快照内按时间倒序逐行消费。比较桶平移当前桶的相对时间覆盖，不对不同长度时段直接按索引比较。
