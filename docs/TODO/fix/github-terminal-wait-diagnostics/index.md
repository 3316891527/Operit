# GitHub 同名终端调用的并发关闭修补与等待诊断

用户多次观察 GitHub 包的短命令等待四至五分钟，点击取消也无法结束。#277 已接通普通同步 exec 的调用方取消任务，但没有定位最初等待发生在哪个阶段。本次在图片诊断 #278 之后继续调查。

`timeout 20 gh ...` 只限制命令中的 gh 子进程；终端工具还会获取引擎、创建或复用会话、等待命令完成事件，并在 `close=true` 时等待关闭会话。不能据此将四分钟等待解释为正常，也不能将本次确认的并发关闭缺陷认定为原长等待的唯一原因。

## 已确认的问题与修补

对预先创建的独立诊断会话，并发运行两个各自带 `close=true` 的封装调用。两者取得相同会话 ID，其中一个执行成功并关闭会话，另一个以退出码 -1 失败。整次观测 1474ms。这证明同名会话的关闭会干扰其他调用，没有复现四至五分钟等待。

宿主现在按会话名串行执行 GitHub `terminal_exec` 的完整获取、执行和关闭过程，覆盖流式与同步包调用入口。同名等待发生在租用引擎之前，不占用四个引擎名额；不同名称仍可并行。等待者取消不会执行调用或释放持有者的锁，持有者取消或失败后仍能交接，空闲锁条目按引用计数回收。同步入口的新增等待也继承调用方取消任务。

默认名称和显式名称沿用原协议，未指定与空字符串均为 `github_tools_session`，不修剪显式名称。包内移除模块级单 ID 缓存，每次按请求名称调用宿主现有 create-or-get，保持宿主会话中的目录状态，避免引擎复用时沿用其他名称或已关闭的会话。TypeScript、dist、示例 bundle 与 APK asset 同步更新。

本修补协调经包管理器进入的 GitHub 终端调用，不协调其他包直接操作同名终端或脚本内部自行并发原生调用。设备并发观测从临时脚本引擎运行封装，用于确认旧行为；修补后的宿主调度需包含本改动的新 APK 验收。

## 等待日志

新增同名会话等待、引擎池等待与租用、脚本执行、GitHub 包 create/exec/close、原生工具调用与结果回传、命令提交与完成及取消的阶段日志。新增诊断只记录关联 ID、会话或命令 ID、阶段与耗时，不记录命令、输出、参数、会话标题或凭据。提交方法返回仅表示提交接口返回，不代表 PTY 已开始执行。

宿主诊断使用现有 ToolPkg 日志，按启动时间归档并最多保留二十份，继续遵循日志写入开关。JS 日志通过脚本回调与宿主调用 ID 关联；桥接日志追加脚本调用 ID、回调与线程 ID，和命令流的会话、线程、命令 ID 联查。原生超时与关闭条件保持原样，不自动重跑命令。

## 设备对照与验证范围

设备使用当前执行应用的诊断副本，原生 exec 期限限定为十二秒，未替换已安装的 GitHub 包：

- 默认会话短命令：create 4625ms、exec 11ms，完整记录 4840ms
- 独立会话短命令并关闭：create 4494ms、exec 26ms、close 22ms，完整记录 4709ms
- 独立会话只读 gh 请求：create 4838ms、exec 8087ms 后收到 shell timeout 的退出码 124，完整记录 13128ms。十秒广播等待先超时，脚本仍正常保存结果；未重复提交。失败路径按既有行为未进入 close，随后单独清理该诊断会话

这些是单次设备观测。独立入口未覆盖聊天引擎池、工作区归属或本轮新增 Kotlin 日志，不能用来证明原长等待已修复。原始消息和设备证据只保存在本机，文档不含设备私有路径或真实会话 ID。

新增八项 JVM 回归源码，真实调用生产会话门禁：同名获取、执行和关闭全程串行，异名并行，等待者取消，持有者取消与异常后的交接，预取消，以及名称规则。使用 Deferred 确定性协调，不依赖固定延迟；本地不执行项目编译或测试。
