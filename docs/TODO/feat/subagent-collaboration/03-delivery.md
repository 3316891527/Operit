用户明确要求默认只交付 Debug。推送修订后通过 Build 工作流显式选择 assembleDebug，publish_release=false，不使用发行变体。目标 APK 为 app-debug.apk，包名 com.ai.assistance.operit.debug，成功产物位于该运行的 operit-android-<run_number> artifact。构建链接与对应提交记录在 PR 说明中。

推送后同时派发 Android Tests，执行仓库已有 JVM 测试与回归检查。确认工作流已启动后不持续轮询，运行链接便于用户查看最终结论。派发成功不代表编译或测试通过；本轮未做真机验收。

用户已安装首版并做简单测试，本轮界面、自动归档和动态思考仍需安装新 Debug 包确认：

- 添加模型只显示当前组，折叠与搜索正常，切组不删除已有模型池条目
- 主代理可为不同难度选择不同思考档位，多轮工具请求保持选择
- 短列表窗口收缩，长过程与子会话滚动，键盘出现时操作可达
- 成功自动归档后托盘隐藏，报告正常回到主代理，报告卡仍能查看和恢复归档任务
- 关闭自动归档或单次覆盖后，成功任务保留在已完成筛选
- 失败、停止、中断保留待处理；既有完整子会话、补充、继续与删除行为正常

第二批安装验收还包括：中文工具说明与非中文英文说明切换；报告中的列表、链接和代码块；none／all／最近轮数的继承范围及继续后背景保留；并发调低不中断现有任务、调高释放排队任务；1 分钟时限的新执行使用动态超时提示，旧执行仍保留原时限。
