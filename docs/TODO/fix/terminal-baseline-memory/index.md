# 终端观察基线内存优化

全盘终端观察为每个文件长期保存基线对象，并在事件采集时复制完整映射。文件规模达到约三十万条时，基线、路径、集合与目录监听共同造成明显内存压力。已有 JSON 的流式输入仍会构造整份映射，不能解决对象常驻问题。

本次保持观察根、文件差异、执行来源与历史还原接口，使用磁盘索引保存文件状态和快照引用。初次扫描与事件扫描分批写入暂存代次，事件只替换命中子树；使用有上限的查询缓存。冷启动期间的已处理路径放入数据库，避免后台扫描覆盖新状态。旧 JSON 逐项迁移，确认提交后移除旧清单；读取或迁移错误明确报告。

## 步骤

1. [磁盘索引与流式扫描](01-index-and-scan.md)：建立按路径查询、暂存扫描、分页差异与有上限缓存，保留不可读、软链接和预算语义。
2. [日志接入和引用清理](02-journal-and-cleanup.md)：替换整份基线持有、复制与异步 JSON 写入，审计历史和在途快照引用，关闭时释放资源。
3. [规模验证与组合交付](03-verification.md)：覆盖同时间戳写入、目录改名、冷启动竞态、失败与重启，验证三十万条索引下的内存边界，并发起组合 Debug 构建和测试。

目录监听仍需要与目录规模相称的系统资源。本次保留现有实时覆盖，测量并说明这部分剩余成本。设备日志、堆快照、真实路径和内容不提交到公开仓库。

代码及本地回归已完成，完整组合 CI、设备验收与实际运行数据清理仍待完成。具体边界见上述验证记录。
