# 增量历史与持久化边界

本轮从 `86bcec63` 继续。约 1 MiB 内容分卷和 SHA-256 身份继续使用，操作 JSON 改为与 `snapshot_objects` 共用数据库和连接的 `operation_records` 表。数据库文件仍为 `objects-v2.sqlite`，操作表采用附加表，不改写已有位置索引格式。

记录保留原始 ID、操作 ID、对话、时间、工具来源、执行和子任务身份、路径及两侧快照。路径原文用于读写；额外保存规范历史路径，以识别 Android 与本地 Linux 的共享存储别名。远端后端身份继续独立。

## 增量更新

终端每次只查询本批的操作 ID 与规范路径，不再加载同次执行的完整清单。已有路径保留最早记录 ID、时间和 before，after 更新为本批的最新快照。可比较文件恢复为原内容时删除该行；过大或不可读快照继续保留，避免把未知内容误认为相同。

旧 `operations/*.json` 逐文件、逐数组元素读取，一个文件的导入和导入标记共用事务。解析失败、身份不匹配或取消时保留源文件且撤销该文件的导入；事务提交后再删除源文件。标记使提交后、删源前的中断不会复活随后已清理的记录。没有全量 JSON 读取的第二条生产写入路径。

## 批次边界

采集只在堆中保存最多 128 个待发布位置，不持有相应的内容数组。累计记录字节约 1 MiB、数量达 128、跨卷或结束采集时提交。单个合法对象最大 2 MiB，超过目标卷大小的对象仍使用完整独立记录。

先同步卷内容，新卷再同步目录项，然后以同一连接的一笔事务发布位置和本批操作记录。扫描期间先固化的对象位置可以早于操作记录；不能先发布引用未提交位置的操作或正式基线。索引提交失败后清除待发布位置并关闭卷句柄，下次按已提交边界恢复尾部。

终端和工作区监视基线均使用有界缓冲的 SQLite 行。暂存内容租约与暂存基线行同批写入，尚未刷盘的租约最多 128 个并参与清理引用检查。同步内容的回调在基线锁外执行，避免清理路径的锁顺序反转。正式基线发布前确认新采集哈希确已提交；失败与取消清除暂存代次。

## 查询和清理

首页的最近产出入口只查询当前对话的最新一条操作，不再因历史版本变化重建完整对话清单。历史文件列表每页最多 128 个摘要，每个文件仅携带最早与最新记录。单文件操作菜单独立分页，翻页替换当前页。搜索在数据库中按整个作用域执行，文件的上一项与下一项可跨页；项目树选中未在当前页的变更文件时按路径查询摘要。

最近轮次先在完整对话中确定包含操作的用户请求，再按工作区范围筛选。这样工作区内没有最新轮次的变更时不会错误显示更早轮次。

摘要列表使用已保存的单次统计。跨多次操作的精确汇总差异在打开详情时按首 before 与末 after 计算；尚未取得的统计使用现有未知状态，不把当前页之和当作全部文件统计。正文和高亮缓存维持 12 项、4 Mi 字符限制，文件详情的可保存状态也限制为最近 12 个文件，每个文件仅保留最近 12 个快照视图选择。

删除全部历史先查询数量和确认时的记录边界，再每页删除，确认后新增的操作继续保留。每页只核对这一页的候选哈希，通过 SQL 查询其他操作、工作区基线、终端基线和在途租约引用。未打开的基线连接逐个打开、查询和关闭，避免清理后常驻全部历史数据库。

## 兼容与验证入口

旧历史会在新存储入口使用时迁移，原记录 ID、操作 ID、时间戳、来源、子任务身份及两侧快照引用继续保留。内容卷格式和目录入口保持原样。迁移成功并删除源 JSON 后，旧 APK 不认识新增操作表，不能读取这部分已迁移的操作历史；本轮不新增旧格式双写路径。

本轮开发验证仅使用观察器排除的临时目录，没有迁移或清理真实用户历史。

生产 Store 提供显式根目录、数据库工厂和目录同步构造器，Android 的 Context 构造入口保持原样。JVM 回归借此执行相同生产逻辑、真实文件与 SQLite；平台挂载路径、日志和 Android 原子文件工具使用验证桥接。公开 Android `android.system` 类用于适配器兼容检查。

标准回归入口为 `:app:testDebugUnitTest`，新增 `WorkspaceHistoryIndexTest`、`WorkspaceHistoryBatchTest`、`WorkspaceHistoryStoreTest`、`WorkspaceIndexedScanTest`。完整 Android 构建和仪器测试编译由 CI 执行，JVM 结果不代表设备上的完整运行验证。

详细验证范围见[验证记录](02-validation.md)，规模结果见[中间版本对照](03-pipeline-measurement.md)。
