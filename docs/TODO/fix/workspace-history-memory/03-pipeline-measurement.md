# 五千与两万文件的中间版本对照

## 版本与测量范围

旧实现来自 PR #253 的 `86bcec630d2bec4ddfc8d27d513c3cc6a1888eb7`，已经采用约 1 MiB 内容分卷。对照实现加入操作记录增量写入、内容与基线批量提交、历史摘要分页，但测量早于最终 rowid 正文布局、搜索字段及后续收尾修改。以下数字只作为中间版本证据，最终版本未复测。

两组各使用独立串行 JVM、64 MiB 最大 Java 堆和真实临时文件，输入为 5,000 或 20,000 个内容不同的 1 KiB 文件。使用真实 SQLite JDBC 3.46.1.3，内容位置与记录库采用 FULL 同步，覆盖扫描、快照、操作合并、基线发布和遍历历史摘要。各组负载目录已删除，没有操作用户真实历史。

JVM 使用 OpenJDK 17 ARM64、`-Xms16m -Xmx64m -XX:+UseSerialGC -XX:ActiveProcessorCount=1`。每 10 ms 采样 Java 堆，同时记录 GC、当前线程累计分配、文件字节以及 `/proc/self/io` 差值。原始指标见[机器可读对照记录](pipeline-intermediate.json)。

## 五千文件

旧实现保存 33.551 秒、历史查询 6.164 秒，合计 39.715 秒；中间批次实现保存 23.766 秒、历史查询 0.502 秒，合计 24.268 秒。

采样最大 Java 堆由 35.36 MiB 降至 8.23 MiB。GC 后仍打开 Store 时为 3.91 MiB 与 3.77 MiB。当前线程累计分配由 1,365,837,336 字节降至 320,113,440 字节；GC 次数由 213 降至 70，累计 GC 时间由 1,282 ms 降至 96 ms。

记录文件总字节由 12,963,283 增至 18,005,408。`wchar` 由 291,187,164 降至 224,644,144，`write_bytes` 由 703,201,280 降至 428,515,328，写系统调用由 146,894 降至 134,362；`rchar` 则由 142,399,238 增至 297,777,121。改善同时伴随数据库空间和逻辑读流量增加。

## 两万文件

中间批次实现保存 161.217 秒、历史查询 2.927 秒，合计 164.144 秒。采样最大 Java 堆 8.23 MiB，Store 打开状态的 GC 后堆为 3.67 MiB；当前线程累计分配 1,226,041,488 字节，GC 269 次、累计 356 ms，文件总字节为 72,205,904。

`wchar` 为 1,578,982,248，`write_bytes` 为 2,918,948,864，写系统调用 825,734，`rchar` 为 2,924,549,554。此阶段观察到 I/O 随规模增加较多，后续把 operation_records 从随机 UUID 正文主键改为 rowid 顺序正文和小型唯一 ID 索引，同时加入搜索字段；最终布局没有取得复测数字，不能推定这些指标已降至某个数值。

旧实现在整份操作 JSON 编码期间出现 `OutOfMemoryError: Java heap space`，栈涉及 JsonToStringWriter 扩容及 StreamingJsonEncoder/FileChangeRecord 序列化，因此没有可比较的两万文件完成耗时。

## 解释边界

10 ms 堆采样不是精确峰值，累计分配量不代表同时存活的内存，`write_bytes` 也不是闪存物理写入量。64 MiB 只限制被测子 JVM 的 Java 堆，不限制 Kotlin 编译器、SQLite 原生分配或宿主应用内存。

本测量不覆盖 Android 文件观察器调度、Compose 渲染、模型并发、宿主原生内存或长时间实机使用。临时基准中的 Java 堆溢出不是应用两次原生闪退的诊断；闪退原因尚未调查。本轮已停止手机上的新增编译和测量，最终 Android 行为由远端构建及之后的设备验证确认。
