# 终端文件变化采集与来源

## 问题与结果

文件工具直接保存操作前后快照；原有终端文件观察依赖工作区绑定。未绑定工作区时，终端中的 Python 等程序创建或修改文件不会进入对话历史。文件通知晚于执行作用域结束时，还可能丢失已知工具来源。

本次在应用共享终端接口接入文件事件日志，按本地 Linux 根文件系统和可访问的映射挂载建立观察范围。文件采集不依赖工作区绑定，不解析命令内容，也不为 `super_admin`、GitHub 包或其他插件分别添加判断。

## 实现

- `TerminalObservationRoots` 复用固定终端子模块中的 PRoot 挂载定义，按物理目录去重，为 Linux 根和挂载源保留代表路径
- `TerminalObservedFiles` 建立修改前基线，根据事件增量重读子树；文件最大快照 2 MiB，每轮每个观察根的读取预算为 64 MiB，预算不足明确保留不可用状态
- `TerminalFileJournal` 统一管理目录观察、活跃执行、交互输入、快照持久化及错误。命令结束前通过 Android FileObserver 的共享事件队列标记等待先前通知，再读取最终内容
- 应用 `Terminal` 的普通、流式、托管及隐藏执行统一关联来源；托管执行在创建 Flow 前恢复原始上下文。交互输入保留提供的调用者，独立调用标为 `terminal`
- 记录分别保存完整调用名称、执行编号和 `terminal` 类别；并发执行无法唯一判断时仍使用终端类别。文件系统监听是采集方式，不作为已知终端记录的调用者名称
- 文件工具继续直接记录，并同步推进相应观察基线，避免同一次写入重复入账。长任务分批更新保留最早的 before 和最新的 after，清除进行中记录不会使旧记录复活
- 目录观察不跟随软链接递归，链接内容只保存目标文本。采集排除虚拟文件系统、Git 元数据、自身存储、缓存、数据库及应用日志；销毁时停止观察器和事件屏障
- 新模型字段提供默认值，旧操作记录可继续读取。清理历史时保留持久化基线及活跃基线仍需引用的内容对象

## 范围与限制

观察范围是本地终端中应用可访问的真实文件目录，包含 Linux 根文件系统和可访问的挂载源。SSH 远端文件、绕过应用 `Terminal` 的内置终端 UI 直连、虚拟文件系统及已排除的应用内部目录不由这条新增链路采集。

首次使用需要枚举目录并建立基线，成本随目录规模增长。读取预算只约束内容字节数，不约束目录或观察器数量；操作系统观察器上限、事件溢出及离线不可读范围仍可能影响覆盖。超过快照上限的文件可以保留变化信息，但没有完整文本差异；文件通知之间发生后又被撤销的短暂写入不会逐次留档。

FileObserver 不提供可靠的写入进程身份。并发写入只能依据活跃终端执行关联来源，不能保证排除同时发生的外部写入；跨对话同时执行时，来源归为全局终端记录，不任意选择某个对话。空闲且无交互归属的事件只推进基线，脱离已完成命令继续运行的子进程不保证进入原执行记录。托管任务在实际执行结束前持续保留来源。

本分支以 PR #222 的远端提交 `4c45381649ab961b3aae05d6675d432bb41a0bde` 为直接基线，完整保留其操作面板、汇总、Diff 加载、展开状态和工作区采集。PR #224 的目标分支为 #222 的 `fix/workspace-import-performance`，审核时只显示本次增量；构建使用 #224 的完整分支，产物同时包含 #222 和本次终端修复。

绑定目录中的变化继续由 #222 的观察器发现。通知会保存共享终端是否已接管该路径的信息，终端负责的写入只推进工作区基线，终端保存后再确认相同快照，避免执行结束后的旧通知产生重复记录或 `filesystem` 标签。没有经过终端的工作区变化仍保留原有采集行为。统计计算继续遵守 #222 的自动加载阈值。

## 测试包与复现

安装 PR #224 最新提交对应的 Debug Build 产物即可测试组合功能，无需先手工合并 #222。此前从 `dev` 独立构建的 #224 产物不能用于验收此组合。

- 不绑定工作区，依次使用文件工具创建、修改同一文本，再通过终端中的 Python 追加内容，核对三次操作及汇总最终内容
- 绑定工作区重复上述过程，核对每次变化只记录一次，终端来源保留调用者或终端类别
- 在绑定目录中执行托管终端任务，工具返回后让实际任务继续写入，核对完成内容和操作归属

浏览器浮窗修复仍在独立的 PR #223，不属于本次基线调整。
