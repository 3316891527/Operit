# 配置与模型选择

[返回计划](index.md)

模型配置的页签依次为连接、参数、上下文总结、子代理配置和功能模型。子代理提示词与模型池均为全局配置，不属于当前正在编辑的某个连接配置。

## 提示词配置

在“子代理配置”中维护名称、用途描述、独立提示词与启用状态。主代理读到名称和用途，用于决定什么时候调用这类帮手；实际子代理收到独立提示词和本次任务简报。配置标识由程序维护，无需用户输入。

提示词不固定模型。修改或删除提示词不会改写已经派发任务保存的指令快照。继续现有任务时保留该任务的提示词快照。

编辑窗口提供保存与取消。取消明确丢弃当前草稿，有修改时使用关闭按钮会先确认；页面切换通过现有保存协调器处理有效草稿，校验或保存失败时阻止离页并显示错误。

## 多选模型池

在功能模型页打开“子代理模型池”，从当前选中配置组内的具体型号中逐项添加。选择器以配置为折叠单元，显示已选数量，可搜索配置名和型号，展开后逐项惰性布局。切换配置组只改变添加范围，已经加入的全局模型池条目保留。每项可启用或停用，必须填写适合的任务与能力，可以补充限制或偏好。同一配置中的同一型号不会重复添加。

建议根据实际使用填写，例如“适合长文分析和代码审阅；复杂任务优先，输出速度较慢”。不要求用户给模型编写系统提示词。模型的能力描述与提示词配置承担不同职责。

目录同时提供已经配置的上下文容量、直读图片／音频／视频开关及原生工具调用开关。这些是配置事实，并非运行基准，也不推断模型质量、价格或速度。主代理被要求依据目录选择，避免使用过时的型号知识猜测新模型能力。

初始模型池为空，提供一套“通用帮手”提示词。没有可用模型时，不能派发子代理任务，也不会自动改用主聊天模型。

## 每次执行的思考与归档

模型目录公布实际思考规则的控制方式、是否必需，以及可选档位的精确 ID 和显示标签。主代理在每次派发时明确选择 enable_thinking；开启分档模型时必须选择目录中的 thinking_option_id。继续执行可重新选择；同型号省略时沿用上次选择，换模型必须明确选择。不存在的档位、不支持的思考控制及必需思考模型的关闭请求会被拒绝。

思考规则沿用型号、提供方和端点共同匹配的现有配置，不另设固定强度界面，不改写主聊天或全局模型偏好。取得实际模型租约后再次校验，首次请求及后续工具轮次使用同一次执行的选择。

“子代理配置”提供“完成后自动归档”，默认开启，用于之后派发或继续的执行。主代理可通过工具的 auto_archive 为某一次执行明确覆盖。只在成功结束时归档；失败、停止和中断留在未归档列表。旧任务保留自己的归档状态，不会在升级或接收报告时批量自动归档。

## 并发与时限

“子代理配置”提供运行限制编辑。全局并发为 1～64，每个主聊天的并发为 1～全局上限，每次执行时限为 1～120 分钟；初始值为 6、3 和 20。每聊天并发由整棵根会话树共用，等待中的子代理让出名额；最大深度默认 3，可设为 1～8，主代理为第 0 层。保存时校验整个限制对象，并在 DataStore 事务中与提示词、模型池和自动归档设置合并。编辑窗口支持保存、丢弃确认和离页草稿校验。

并发限制用于后续调度，调低不会取消正在运行的任务；增加名额会调度已有排队任务。派发或继续时捕获当前执行时限，等待队列不计时；运行中的执行不跟随之后的设置修改。旧配置使用原有并发数和 20 分钟时限，旧任务仍为独立背景且保留原状态，无需清空数据。

## 模型引用与执行快照

模型池按配置标识和具体模型名称引用。派发与执行开始时校验池条目仍启用、配置存在、型号仍在配置中。缺失或禁用会明确报错，用户可修正配置后继续任务。

实际模型租约在一次执行内固定服务、配置和请求参数。读取配置时要求真实存在且能解码；型号按同一份配置解析，避免修改型号排序后选到另一个模型。运行中的任务使用已经取得的租约，后续配置修改在新执行时生效。自定义参数解码或类型转换失败会明确报错；共用参数读取入口也会保留这一错误，避免缺少参数继续请求。

继续任务默认仍使用原模型池条目。主代理也可以明确选择池内另一项，任务详情与每次报告记录当次的模型名称。主聊天模型的功能映射不受委派影响。

全局配置保存在独立的版本化 DataStore 中，修改按事务合并。提示词最多 32 项，模型池最多 64 项；数量和字段长度在保存时校验。
