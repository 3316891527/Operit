# 录音配置拒绝与系统侧滑排除

## 设备反馈与原因

PR #232 的设备验收已确认编辑器滚动与背景模糊有效。录音在模型缺少 API 配置时显示顶部配置错误，但录音浮层把所有发送拒绝都显示为独立发送条件不满足，保留发送重试和取消按钮。用户要求配置无效时仅显示顶部错误，关闭浮层并丢弃本次未发送音频。

现有普通发送管线已在消息落库前校验实际模型配置。本次为语音返回独立的配置拒绝结果，保留原校验顺序，阻止该结果进入录音重试界面，也不产生额外的独立发送警告。

OriginOS 超级卡包容易在录音滑动时触发。原长按指针流属于聊天主窗口，现有录音窗口副作用却在非焦点 Popup 内容中安装，侧边排除未覆盖原手势所属窗口。Popup 的系统手势排除也不能替代主窗口的排除设置。

## 实现范围

- 为语音发送区分已落库、配置拒绝和其他状态拒绝，配置拒绝立即关闭浮层并清理未发送文件
- 配置错误继续由发送层原有顶部提示展示，不写入语音消息、不触发已发送通知、不保留发送重试界面
- 录音窗口效果移到 Popup 外的主窗口，准备新会话阶段也持有录音窗口效果
- 麦克风按钮在长按判定前就排除系统手势，避免系统在初次按下时已经注册侧滑
- 主窗口根视图请求覆盖全窗口的系统手势排除区域，并在尺寸变化时更新，包含左右边缘；浮层根部也请求完整排除
- 结束、取消、错误、失焦、切换会话或离开页面时恢复原排除区域、导航栏显示状态、系统栏行为和常亮状态

## 平台边界与验收

Android 普通应用不能彻底禁用强制 Home、最近任务、通知栏及厂商独立拦截的手势。排除请求由系统裁定，普通返回侧滑排除还可能受系统范围限制。厂商手势是否遵循排除区域需在对应 OriginOS 设备复测；本次不修改设备全局手势设置。系统仍抢走窗口时继续安全取消录音，不将中断伪装成松手发送。

- 无密钥的远程模型：松手后仅顶部配置错误，录音界面关闭，历史不新增本次语音，临时文件删除
- 有效配置：松手正常发送，落库文件保留；本地模型、账号认证和自定义提供商继续使用已有配置契约
- 草稿、附件、引用或原聊天状态改变：沿用原独立发送限制
- 左侧取消、右侧转文字：原手势行为保持，系统中断继续取消
- OriginOS：录音期间从左右边缘及底部滑动，复核超级卡包误触与系统手势效果；结束后正常侧滑和系统栏恢复
