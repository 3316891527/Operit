# A2UI 完整实机测试

本清单覆盖原生生成、直接围栏、55 种组件、交互、持久化、live 更新和异常处理，保留此前已检查的基础项目。本轮所有结果先留空，不将截图或旧版结果自动记为通过。

安装本轮 `feat/distribution-a2ui` 的 Operit Debug。先用可调用 A2UI 工具的角色；原生生成与直接围栏项目不需要引导包。需要示例时导入更新后的 `a2ui_guide.js`，通过 read_example 读取源码后再调用原生工具生成。已经注入过旧说明的角色应替换为本轮说明，重新开一个聊天再测。示例数据均为演示数据。

普通保存与恢复使用本轮新建卡片；旧调试版私有目录的填写状态不作迁移要求。每项失败记编号、实际现象和工具原始参数/错误；无法创造条件的项目填“未测”。

## 可复制提示

A：基础表单。用于 02、12～15、30～34。

```text
请查询 a2ui_catalog，再使用原生 a2ui_prepare 生成表单：姓名输入框、开关、本地保存、取消编辑、提交给 AI。初始姓名为空、开关关闭，输入绑定普通用户路径；填写仅在本地，提交前需确认。卡片前后各写一句普通文字。不要读取引导包。
```

B：直接协议渲染。用于 03；请同时查看回复源码，避免把模型只回复普通文字误记为通过。

````text
不要调用生成工具。原样输出下面的完整围栏，不要改为普通文字：
```a2ui
{"version":"v0.9","createSurface":{"surfaceId":"directcheck","catalogId":"https://operit.ai/a2ui/catalog/v1"}}
{"version":"v0.9","updateComponents":{"surfaceId":"directcheck","components":[{"id":"root","component":"Card","child":"body"},{"id":"body","component":"Column","children":["title","text"]},{"id":"title","component":"Heading","text":"直接围栏检查"},{"id":"text","component":"Text","text":"命名检查通过"}]}}
```
````

C：live 成功路径。用于 36、37。三个进度值可能很快跳过，至少核对最终界面和两次工具返回版本。

```text
严格使用下面 Express 源码调用 a2ui_prepare(source=源码,live=true)：
$/agent={progress:10}
root=Card(child=Column(children=[Display(label="progress",text=concat(values=[$/agent/progress])),Progress(label="实时进度",number=divide(a=$/agent/progress,b=100))]))
先在正文输出返回引用的 a2ui-ref 围栏，再在同一轮结束前调用两次 a2ui_patch_data：
第一次 expected_version=0，data={"progress":50}；
第二次 expected_version=1，data={"progress":100}。
data 不包裹 agent 键。不重新生成卡片，不重复输出引用，最后告诉我两次返回的 version。
```

D：复现本次错误及恢复。用于 38，允许模型执行这里明确要求的无效输入。

```text
在同一轮先后用 live=true 调用 a2ui_prepare 测试下面两段无效源码。不要提前修复它们，分别报告返回的 code 和 message：
第一段：
$/progress=10
root=Card(child=Progress(number=$/progress,label="代理数据 progress"))
第二段：
$/agent=10
root=Progress(number=$/agent)
完成后再用以下正确源码生成，并展示最终引用：
$/agent={progress:10}
root=Progress(label="修正后",number=divide(a=$/agent/progress,b=100))
```

E：版本冲突。用于 39，所有调用在同一轮完成。

```text
严格使用下面源码调用 a2ui_prepare(source=源码,live=true)，先在正文展示返回引用的 a2ui-ref 围栏：
$/agent={progress:10}
root=Progress(label="版本检查",number=divide(a=$/agent/progress,b=100))
在同一轮以 expected_version=0、data={"progress":50} 更新；再故意用 expected_version=0、data={"progress":90} 更新一次；最后用 expected_version=1、data={"progress":100} 更新。报告每次是否成功和返回版本，不换卡片，不重复输出引用。预期第二次失败，最终版本为 2。
```

F：用户数据隔离。用于 40，先检查拒绝，再用修正后的卡片测试更新与输入。

```text
先以 live=true 传入下面源码，报告结果，不提前修正：
$/agent={name:"演示"}
root=TextField(label="错误绑定",value=$/agent/name)
随后改用独立用户路径和 Agent 路径生成可交互 live 卡片：
$/name="测试123"
$/agent={progress:10}
root=Column(children=[TextField(label="姓名",value=$/name),Progress(label="进度",number=divide(a=$/agent/progress,b=100))])
在同一轮更新 Agent 为 {"progress":100}，确认姓名仍为“测试123”。卡片显示后我会手动修改姓名、切换聊天并查看保存状态。
```

组件示例：对 18～24 可直接发“读取更新的 a2ui_guide 中的指定示例，保持示例语义，用原生工具生成”。其他项目让模型先查原生目录，再按表中的组件名生成；无法生成时展开工具参数，区分输入源码错误与宿主运行错误。
