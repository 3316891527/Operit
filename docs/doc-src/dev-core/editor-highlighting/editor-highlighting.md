# 编辑器自定义语法高亮

工作区编辑器和文件变更 Diff 共用动态样式与 TextMate 分词。浅色默认使用 Atom One Light 风格；自定义配置采用严格 JSON，版本为 1。这是一套独立的轻量格式，不直接读取 MTSX。

## 配置位置与生效

应用私有目录为 `files/config/editor/highlighting/`，由 `Context.filesDir` 定位，不固定包名。目录在首次打开编辑器、Diff 或识别陌生文件关联时创建。

```text
highlighting/
	_global.json
	markdown.json
	kotlin.json
	demolang.json
```

`_global.json` 只允许 `version`、`styles` 和 `scopes`，用于所有文本的样式设置。其他 JSON 以语言 ID 命名，可以定义样式和匹配规则；语言别名会统一为 TextMate 目录中的 ID，同一 ID 不能由多个文件重复定义。

保存、移动或删除配置文件后，已打开的编辑器会在短暂合并文件事件后自动重新分析，也会在窗口重新获得焦点时读取配置。普通输入不扫描配置目录。Diff 在打开和点击刷新时读取配置。主题切换只更新绘制样式，不重新分词。

新建的零字节或仅包含空白字符的 JSON 文件保持待编辑状态，不参与规则加载，也不提示配置错误。填入内容并保存后才参与整组校验；空文件仍计入文件数量和容量限制。

配置整组校验后生效。重复键、未知字段、未知引用、非法正则、颜色或版本会报告错误，不继续使用上一个配置修订。修正文件后，编辑器重新加载；Diff 可点击刷新。

可复制[全局示例](examples/_global.json)、[Markdown 示例](examples/markdown.json)或[完整自定义语言示例](examples/demolang.json)。[示例目录](examples/README.md)附有对应文本。[JSON Schema](editor-highlighting.schema.json)可用于编辑器外部校验，全局文件使用其中的 `#/$defs/global` 定义，语言文件使用根定义；引用存在性和运行限额仍由应用检查。不要把 schema 文件复制到运行配置目录。

## 样式与 scope

样式名由配置自由声明，允许中文；软件不需要为新名字增加分类接口。

```json
{
  "version": 1,
  "styles": {
    "运算符": { "light": "#0184BC", "dark": "#56B6C2" },
    "重要标记": { "extends": "keyword", "bold": true }
  },
  "scopes": [
    { "scope": "keyword.operator", "style": "运算符" }
  ]
}
```

每个样式支持 `extends`、`light`、`dark`、`bold`、`italic`、`underline` 和 `strike`。颜色采用 `#RRGGBB`，字体属性是布尔值，显式 `false` 可以关闭继承效果。属性按内置、全局和语言配置逐字段合并，随后解析命名样式继承；循环继承和不存在的父样式会报错。

内置名字包含 `default`、`keyword`、`function`、`string`、`number`、`comment`、`type`、`variable`、`operator`、`punctuation`，以及 `heading`、`headingMarker`、`bold`、`italic`、`underline`、`strikethrough`、`link`、`quote`、`list` 和 `inlineCode`、`tag`。没有指定颜色的字体样式可以叠加外层颜色，例如粗体中的斜体。

`scopes` 匹配 TextMate 已识别的 scope 前缀。例如 `keyword.operator` 同时匹配 `keyword.operator.arithmetic.kotlin`。这里只接受一个 scope 前缀，不接受通配符或完整 TextMate selector 表达式。每层先应用较短前缀，再应用较长前缀；相同前缀按声明顺序应用，语言条目排列在全局条目之后。内层 scope 可以覆盖外层属性。

默认已经保留 Markdown 的标题、粗体、斜体、删除线、链接、引用、列表标记与行内代码样式。内置语法标注的嵌入代码和插值边界会结束外层文档或字符串样式的继承。自定义区域可用 `contentStyle: "default"` 同时恢复默认颜色和字体属性。

## 规则模式与顺序

语言文件可以省略 `mode`，此时为 `extend`：自定义规则排在当前内置语言的根规则前面。`replace` 使用配置中的完整规则，必须提供非空 `rules`。新语言 ID 使用 `replace`。

所有候选中，匹配位置靠前的获胜；同位置按规则顺序决定，不自动选择最长规则。`literals` 和 `words` 各自内部会把较长词项排在前面。

扩展规则与内置规则也会竞争起点。例如把 `/` 放在内置规则前面会抢占 `//` 或 `/*`。给现成运算符换色可使用 scope 映射；编写完整语法时，将字符串和注释区域排在普通符号前面，并在相应区域内声明子规则。

## 匹配器

每条规则必须在 `match`、`words`、`literals`、`begin`、`include` 和 `language` 中选择一种类型。

- `match` 使用正则，可设置 `style` 和 `captures`
- `words` 接收词表，自动添加字母、组合标记、数字、下划线和美元符号的标识符边界
- `literals` 接收精确文本列表，自动转义正则特殊字符，适合运算符和固定标记
- `begin` 与 `end` 定义区域，内部用 `rules` 继续匹配
- `include` 引用当前文件 `definitions` 中的规则组
- `language` 引用内置或已配置的语言 ID，用于嵌入另一种语言

`match`、`words`、`literals` 和区域规则可使用 `ignoreCase: true`。正则使用现有引擎的 Joni / Oniguruma 语法，和 MTSX 文档中的 JDK 方言存在差异。JSON 中的反斜杠需要转义。单个匹配器按行运行，多行结构应通过区域规则保存状态。

```json
{
  "version": 1,
  "mode": "replace",
  "styles": {
    "声明名": { "light": "#986801", "dark": "#E5C07B", "bold": true }
  },
  "rules": [
    {
      "match": "\\b(class)\\s+([A-Za-z_][A-Za-z0-9_]*)",
      "captures": { "1": "keyword", "2": "声明名" }
    },
    { "words": ["if", "else", "return"], "style": "keyword" }
  ]
}
```

`captures` 的键是捕获组序号，`0` 表示整个匹配。区域分别使用 `beginCaptures`、`endCaptures`；`style` 覆盖整个区域，`contentStyle` 只覆盖内部内容。终点可通过 `\\1` 等数字反向引用起点捕获组，引用必须存在。

区域的结束规则默认在同位置竞争时优先，`endLast: true` 将子规则排在结束规则前面，可表达 C# 双写引号等转义。区域未闭合时，状态延续到文件末尾；需要单行恢复时可将 `$` 加入结束表达式。

`definitions` 是名称到规则数组的映射。`include` 还支持 `$self` 引用当前根规则，以及 `$base` 显式引用该语言的内置规则。递归必须经过区域，起点应实际消费文本；纯引用循环和跨语言根引用循环会报错。引用名不执行代码，也不支持表达式拼接或函数调用。

## 自定义文件关联

语言文件可声明 `extensions` 和 `fileNames`。名称匹配忽略大小写，精确文件名优先，后缀使用最长匹配；冲突的关联会报错。这些关联同时用于文件打开和高亮规则选择。原本交给系统打开的陌生格式，例如 `.operitdemo`，在关联有效且内容采样确认为文本时默认进入内置编辑器。工作区浏览器、文件链接和从归档中打开的文件共用该入口，重新打开时读取最新关联。

二进制内容仍由系统处理，已有媒体、文档预览和归档入口保持各自的打开方式。内置源码与媒体共用后缀时继续由内容采样区分。普通 JSON 文件不依赖自定义关联识别，因此非法配置本身仍可以打开修正。

## 默认文本打开

确定的文本格式由 `KnownTextFiles` 统一提供 MIME，供附件导入、历史附件预览、附件外部打开和工作区文件 MIME 使用。工作区浏览器、路径链接、归档解压后的打开入口沿用共享文件路由；工作区分享和本地预览服务器沿用同一 MIME 识别。

默认规则明确包含 `.log`，忽略扩展名大小写；同时覆盖常见源码、`.csv`、`.tsv`、`.jsonc`、`.json5`、`.jsonl`、`.ndjson`、`.toml`、`.ini`、`.conf`、`.config`、`.cfg`、`.cnf`、`.properties`、`.env`，以及 `README`、`LICENSE`、`NOTICE`、`Makefile`、`Dockerfile` 等确定的文本名称。SAF 导入即使报告通用二进制 MIME，也按显示名称识别这些格式；旧聊天记录中的通用 MIME 同样在预览时重新识别，无需迁移记录。

附件文本预览保留 512 KiB 限制，读取前沿用 512 字节内容采样；工作区文本读取继续使用原有容量和内容检查。未知二进制扩展名不加入文本规则；`.ts`、`.mts`、`.r`、`.mod` 等存在媒体歧义的后缀不在这份确定文本表中，工作区继续使用原有采样规则，SVG 保留图片预览。

## 边界与验证

目录最多 64 个 JSON 文件，单文件 512 KiB，总计 2 MiB。每文件最多 256 个样式、1024 条规则，规则显式嵌套最多 24 层，单个正则最多 8192 字符。直接引用链最多 64 层，每组配置引用展开最多 8192 个候选规则，经过区域的递归不计作直接展开。加载时拒绝能直接接受空文本的普通匹配或区域起点，分词沿用现有引擎的时间限制与请求取消检查；编写正则仍应避免有歧义的嵌套量词。

本版不支持动态颜色解析、组合匹配器、全部重复捕获记录、失败撤销、预先寻找终点、强制闭合、MTSX 特殊标记、格式化器或压缩器。新样式仍可以自由命名，不受内置颜色角色数量限制。

实现保留已有 UTF-16 坐标、跨行状态、完整文本版本与增量行缓存。配置修订创建新的规则对象，旧快照不会随配置变化而改变。

回归源码覆盖动态样式与捕获坐标、字段继承、字符串和注释上下文、双写引号、多行反向引用、递归、引用循环、错误配置、自定义关联、Markdown 样式、规则缓存、空白文本匹配、配置编码、引用展开限额和主题解析；设备回归覆盖保存配置、错误修订和修复后的自动重载。本地静态检查与远程测试执行结果分别记录，新增回归源码不代表已经运行通过。


## 动态终点与 Markdown 兼容修正

提交 `9b964d5a` 的远程 Android Tests 运行 `43997642863` 共执行 3635 项测试，其中两项失败、15 项跳过。失败分别是动态终点反向引用无法闭合，以及 Markdown 粗体没有生效。

Sora TextMate 0.23.6 在替换终点引用时，先对捕获文本做正则转义，再调用替换模板转义函数；但实际辅助函数只拼接字符串，没有消费第二层转义。`##` 因此无法闭合，`**` 会生成可匹配空文本的终点并过早退出粗体。应用保留原类接口，以直接拼接正则源码的方式修正 `RegExpSource`，同时保留空捕获替换为空文本的语义。固定 AAR 校验继续生效，打包时排除被替换的四个原始类。

失败报告还包含 Markdown 删除线的 Joni 后视错误。规则改用前瞻检查关闭符之后的词边界，并只对关闭符之前的下划线使用固定长度后视；原捕获组、标记长度和边界限制保留，资源原始与当前校验值一并登记。

原有两项失败断言继续保留，补充特殊字符与 Unicode 分隔符、字面量闭合、空捕获、Markdown 闭合后的正文以及删除线边界回归源码。本地静态核对与新提交的远程运行分别记录，源码修正不代表新一轮测试已经通过。


## 源码组织

配置解析、加载、文件关联、动态样式及主题解析统一位于 `workspace/editor/highlight/`。`editor` 保留文档、画布和高亮快照，`editor/textmate` 保留语法目录与引擎注册；编辑器、打开路由与 Diff 显式引用高亮子包。磁盘配置位置和 JSON 版本保持一致。


PR Check 运行 `44001418393` 的设备测试源码编译发现四处缺少必填 `fileName`。所有设备回归调用统一传入实际文件名，三处原有位置参数回调也改为具名 `onCodeChange`，覆盖搜索动画、初始定位、增量会话和自动换行；文件身份仍由独立的 `fileKey` 表达。该修正等待新一轮远程编译和测试确认。
