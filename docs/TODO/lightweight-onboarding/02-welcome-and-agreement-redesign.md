# 欢迎页与用户协议正文接入 [DONE]
本轮在单页首次使用流程的基础上重新设计欢迎页，并将用户提供的完整用户协议草案接入应用内阅读页。
## 欢迎页结构
- 顶部使用小尺寸应用图标和 Operit 名称，不再使用二代页面的大尺寸居中图标
- 中部左对齐展示广告词“让想法，走出对话框”，使用主题色竖线建立视觉重点
- 底部单独放置协议确认区域和唯一的“同意并开始”按钮
- 默认不勾选协议；未勾选时按钮不可用；点击协议名称进入阅读页，返回后保留勾选状态
- 页面没有第二页、配置导入、权限集中授权或额外功能介绍
## 协议正文
- `app/src/main/res/raw/operit_user_agreement_v02.md` 与用户提供的 `01_用户协议_完整草案.md` 保持字节级一致
- 阅读页直接读取该 raw 资源，按 Markdown 标题做基础排版并支持滚动与文本选择
- 应用内标题、勾选入口和设置说明统一使用“用户协议”，没有新增或假设隐私政策
- 欢迎页只保存“已经同意”的布尔状态，不保存协议版本或日期；读取到旧的 `accepted_agreement_version` 记录时保留完成状态并清除旧字段
- 阅读页不展示协议版本行，也不要求等待或滚动到底部；协议正文中原有的草案状态、待确认字段和发布前说明保持不变
- 删除旧的 `agreement_content` 用户协议字符串资源，避免旧正文继续被误用
## 验证
- 九个 `values*` 目录的 `strings.xml` 均通过 XML 解析
- 九种语言均包含 `onboarding_tagline`、`onboarding_consent` 和 `onboarding_start`
- 应用资源与外部草案 SHA-256 一致
- 除协议原文用于 Markdown 换行的行尾空格外，其余源码、资源和文档通过 `git diff --check`
- 未运行本地 Android 构建、单元测试或真机回归；按仓库约定交由远程工作流和后续设备验收
