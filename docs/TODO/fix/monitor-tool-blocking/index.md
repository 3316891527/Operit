# 解除文件监控对工具与目录浏览的阻塞

从 `5212101c` 和 PR #254 继续，贡献分支为 `fix/monitor-tool-blocking`。现有终端采集和工作区扫描共用操作锁，工具执行前后同步调用工作区检查，因此只读文件工具和 Linux 目录浏览也会等待扫描。内部历史日志显示采集曾因缺失快照大量重复失败；18:35 的现场没有日志，不能将已知代码缺陷等同该次卡顿的完整诊断。

## 实施顺序

- 已移除通用工具入口的同步监控钩子，保留真实写入的精确快照及事件归属
- 工作区由文件事件和后台核对采集，只读浏览不再触发工具边界全量扫描；没有明确写入身份的外部变化标记为 filesystem
- 耗时显示已检查到计时记录和消息拆分入口；按紧急更新优先级，本轮不修改计时，保留后续专项调查
- 添加相应回归与兼容说明，轻量检查后提交 PR，派发远端 assembleDebug 与 Android Tests

## 验证与边界

不在手机上新增编译、JVM 测试或规模测量，新增回归交由远端标准测试入口执行。用户最终要求为合并到 dev 与 main 后正式发布紧急修复版本。保留已发布的文件工具参数、调用结果、历史记录与主题接口，不更改日志开关，不清理真实用户历史，也不启动子代理。远端工作流仅确认启动，不持续查询结果。

耗时显示已经出现恢复后再次消失的反馈，本轮同时检查计时数据与 UI 的订阅和索引；不能用推算时间填补缺失的真实执行记录。

## 紧急修复范围

通用工具执行路径和可视化目录浏览不再进入工作区扫描。文件工具的 WorkspaceChangeRecorder、终端的 TerminalFileJournal 和工作区事件观察继续保存真实变化。精确写入来源继续由这两条实际写入路径提供，事件观察不再根据临近只读工具推断来源。

耗时显示与美化不阻塞本次紧急交付，计时问题保留后续调查；本轮不修改计时数据或伪造耗时。
