# 主代理自动委派与子代理协作

用户已选定交互原型，开始实现通用子代理。聊天模型和主聊天入口保持原有职责，主代理决定分工与模型选择。用户查看任务、过程和报告，可以补充与停止；不提供手动新建运行任务或切换主／子代理聊天模型的入口。

## 已确定的配置结构

- 模型配置在“上下文总结”之后增加“子代理配置”，维护名称、用途描述、独立提示词与启用状态
- 提示词配置不绑定某个模型，稳定标识由程序生成，不要求用户填写技术 ID
- 功能模型配置增加独立的多选子代理模型池，仅池内启用的模型可被委派
- 模型池条目可填写擅长任务与使用限制；把这些说明和已配置的客观能力提供给主代理，避免依赖模型名的旧知识猜测
- 模型池引用具体配置与模型名称，运行时验证仍然存在，不静默改用其它模型

## 实施顺序

1. 配置与模型目录：持久化提示词、模型池及能力说明，接入原生配置界面
2. 协作运行时：独立子会话、执行身份、并发队列、消息信箱、可靠结果交接、中断记录与恢复
3. 模型工具与聊天：主代理自动委派，运行时约束权限和深度，紧凑任务卡、详情与任务管理
4. 文档与交付：记录实际实现、检查边界和使用方式，独立分支与 PR
