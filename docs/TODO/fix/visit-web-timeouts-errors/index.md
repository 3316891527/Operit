# visit_web 超时、取消与失败状态

对比 Operit Ry `CATMIAOZHI/Operit` 的 `personal/main` 提交 `5f2b73557fbf787cc3d4f5270b6acd4367adaf66`，其 `StandardWebVisitTool` 已把页面生命周期从 Compose 中拆出，加入不可被重定向重置的加载预算、脚本提取时限、整次访问时限、主页面错误处理与协程取消。其只读界面作为本次适配的来源，保留来源和许可证说明；不引入 Ry 的品牌、Orbit 调用、浏览器配置或发布逻辑。

原实现虽然有基于 `loadToken` 的 10 秒计时，但重定向会重置计时，页面提取和手动等待也没有整次访问时限。超时、取消、显示失败及无效 JSON 会落入旧文本解析路径，构造 `VisitWebResultData`，最终被标记为成功；注册时的阻塞调用还使外层取消无法及时关闭窗口。

本次范围：

- 在独立会话管理加载、等待与提取，加载最多 10 秒，脚本提取最多 3 秒，整次访问最多 30 秒。懒加载等待仍读取原设置，限制在 0～10 秒；最多同时创建 3 个 WebView，排队计入总时限
- 借鉴 Ry 的自动读取流程，取消按钮直接取消，保留缩小与等待期间提前提取；取消自动和无限手动等待不再阻塞工具结果
- 网络、HTTP 主页面错误、证书错误、渲染进程退出、空白内容、错误包与无效 JSON 返回失败及明确原因，不推断是否被墙
- 挂起执行沿用调用方协程；成功、失败、取消和部分初始化失败共用主线程清理，WebView 在组合前同步创建并登记资源所有权，初始化异常直接失败，窗口及 WebView 不留到下一次调用
- JSON 按标准方式解码，保留转义文字；仅成功结果写缓存，链接编号、图片下载和长正文存文件的约定继续保留

对比 Ry 进一步处理 HTTP 错误、空内容、标准 JSON 解码和失败资源清理，并移除将无效内容包装成成功的旧路径。超时直接失败，不用上一次提取的内容代替本次失败。

验证将覆盖重定向、没有页面回调、脚本不回调、取消后晚到回调、等待后新内容及解析失败。JVM 验证和设备验收分别记录，设备上仍需核对可达页面、不可达地址、HTTP 错误、证书错误及停止对话后的窗口清理。
