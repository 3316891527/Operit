# 独立执行与取消

旧实现的 Root 一次性调用使用共享 libsu Shell。流式命令也向同一队列提交，某条命令不能结束时会阻塞后续命令；Builder 初始化超时不限制任务执行。exec 路径还会依次读完两路输出，产生管道背压风险。

本次仅将 `execute_shell` 工具的 Root 路径接入 IsolatedShellCommand。内部 Shell 调用与长期流式接口继续沿用原入口。授权仍由原权限快照选择；一次性调用使用私有 su，exec 模式沿用配置的自定义 su，其他模式使用默认 su。这与 Ry 的托管 Shell 启动方式一致，不向 libsu 主 Shell 提交任务，不进行跨后端重试。每次调用独立，不保留上次的工作目录或 Shell 变量。

执行器以 setsid 建立独立进程组。监督进程先报告组长 PID，收到应用 `go` 后才执行用户命令，防止授权延迟期间取消后仍运行命令。用户 stdin 指向 `/dev/null`；监督进程 stdout 仅承载 PID 和退出码，两行各最多 32 字节。用户 stdout 和 stderr 合并到另一管道，避免输出污染控制消息。

两条管道按可用字节读取，不等待 EOF，也不创建可能永久阻塞的读取线程。每轮读取量有上限，确保连续输出时仍能检查控制消息、取消和期限。输出使用 256 KiB 环形缓冲，超限后继续消费并在结果中明确标记截断。

正常完成后放行监督进程自然退出，再关闭本次描述符，不主动杀后台服务；后台服务应显式重定向输入输出。超时、取消和执行失败先用本次令牌核对 `/proc/PID/cmdline`，再终止本次进程组，清理使用相同 su 配置，最多等待 2 秒。清理失败直接报告错误。另行建立会话的守护进程不属于此进程组。

JS 原生桥接会新建线程。ToolRuntimeContext 增加内部 cancellationJob，Shell 同步入口将它作为 runBlocking 的父任务，使停止对话能取消实际执行。流式入口直接使用调用方协程。取消不会被普通错误处理包装为成功。

Root 日志记录独立调用 ID、期限、结果、取消和耗时，便于后续将未完成调用与任务结束对齐；不依赖用户完整命令判断生命周期。
