## APK 交付与验证状态

本次用户已提出 APK 交付需求。推送修订后通过 Build 工作流派发 `:app:verifyCiPreviewRelease`，保持 `publish_release=false`。该任务生成独立发行身份的 `app-kong.apk`，成功产物位于该运行的 `operit-android-<run_number>` artifact 中；具体运行入口见 PR 说明。构建不发布正式 Release，也不合并 PR。

没有额外运行单元测试或设备测试；不将此前首版源码接入、参考仓库的测试成绩或未结束的构建描述为验证通过。工作流成功派发后不轮询其进度。

安装后仍需确认：

- 从现有 29 版数据库升级后，原聊天、分支、文件夹、归档与用量明细保留
- 并行子任务真实消息、工具过程、型号与统计落盘，普通列表和搜索不出现内部子聊天
- 多次补充与继续保持消息顺序，未消费补充仍明确标记等待应用
- 杀进程重启后保留已写检查点并标记中断，继续不重新创建子聊天
- 单项停止、父停止、清空、分组和角色批量删除不会遗留活动作业或关联记录
- 多模型请求、实际工具取消、后台保活和权限在设备上按预期工作

## 本次范围

只完善完整子会话的数据层，不增加代理树通信、主上下文复制或会话图导入导出界面。普通逻辑导出包含父聊天中的报告，尚不包含完整子会话图。

空闲父聊天不自动启动新轮次，报告在下一轮接收。模型配置失效或数据库读写失败明确报错，不静默换模型。

草稿 PR 用于评审；是否已经构建和验收，以实际工作流及设备记录为准。

## 首轮构建失败与修正

[Build #271](https://github.com/3316891527/Operit/actions/runs/44862348812) 在 `:app:compileReleaseKotlin` 失败。完整日志包含三条编译诊断，对应两处原因：

- `SubagentCatalog` 在 JSON 数组构建块中调用挂起的配置读取。改为先在 `describe` 的协程中读取模型配置快照，再构建 JSON，保留原有模型过滤和能力字段。
- `SubagentTools` 将工具列表作为分类构造器的第二个位置参数，该位置实际是 `categoryHeader`。改为明确传入 `categoryName` 与 `tools`。

本修订只修正上述编译阻塞。差异检查与接口核对完成后推送同一分支并重新派发 APK 构建；新的运行入口记录在 PR #235。新构建结果与安装验收仍需按实际记录判断。
