# 系统状态栏接入

## 旧行为与目标

部件目录原本只有消息 `status` 和应用 `appBar`，不包含显示手机时间、信号和电量的系统顶部栏。窗口状态栏透明，图标明暗只由应用浅深模式决定。

新增 `surfaces.statusBar`，位于工作室“顶栏与导航”组。继续使用现有角色草稿、浅深模式、脚本求值、保存和导入导出流程，不新增独立配置格式。

## 实现边界

- 填色、渐变、图层和不透明度复用现有 surface 绘制，由实际状态栏 Insets 或预览样例的固定尺寸直接确定绘制范围。启用自定义状态栏时，从页面绘制中裁出状态栏区域，保留顶栏、工作区及抽屉的原有布局。`opacity` 为 `0` 时直接露出主题根背景。
- 系统图标只提供跟随主题、深色、浅色三个选项。工作室将后二者保存为 `contentColor` 的黑色或白色；脚本传入其他颜色时，按相对亮度小于 0.5 选择深色，否则选择浅色。省略内容色时保留应用原有的浅深规则。
- 系统控制实际时间、信号、电量、字形与尺寸。surface 的不透明度仅影响背景，不影响系统图标；工作室不开放该区域的字体、留白、最小高度、交互状态或图标素材绑定。
- 编辑预览共用 `ThemeStatusBarBackground`，固定展示 `9:41`、信号和电量样例，不读取设备状态。样例自身不填不透明底色，透明处显示既有草稿背景画布。页面正文继续使用原有页面背景入口。
- 草稿预览使用独立 ThemeScriptHost，样例的设置只应用在画布上。工作室的全屏编辑窗口按编辑器主题设置真实状态栏，两处都遵循浅色主题黑图标、深色主题白图标。

## 兼容性

新应用读取不含 `statusBar` 的旧主题时，不绘制新背景，状态栏仍透明，图标仍采用原来的 `!darkTheme` 规则。消息 `status`、应用 `appBar` 和导航栏行为不变。

旧应用的已知 surface 集合不包含此 ID，会拒绝含 `statusBar` 的工程。API 数字沿用现有值不代表旧应用能够识别新增目标，不作这一兼容承诺。

## 验证记录

新增运行时与预览文件的 `matchParentSize` 只在 BoxScope 内调用，没有普通顶层导入。项目图标子集提供 Smartphone 和 Wifi；信号与电量样例用 Compose Canvas 绘制。
