# 运行时、结果交接与使用边界

[返回计划](index.md)

## 任务与执行身份

`SubagentCoordinator` 是应用级任务所有者。每个任务关联独立的 Room 子聊天，并保存父聊天、发起工具调用、提示词快照、模型池引用、工作区、角色卡与记忆空间。任务 ID 与子聊天 ID 分开保存；模型执行与工作区变更使用真实子聊天身份，再由关联记录归属到父聊天。任务身份、每次执行身份和父工具调用身份分别保存。

`spawn_task` 从可信工具执行上下文取得调用方，不接受模型自报的父聊天或工具调用身份。同一次父工具调用不会重复派发。补充、停止、等待、继续与归档／恢复必须匹配当前执行身份，防止迟到请求影响新执行。

每次执行使用独立的 `EnhancedAIService` 实例与输入信箱。子代理只收到任务简报、自己的历史和补充，不自动复制主聊天完整历史。任务列表、详情和报告均由真实任务状态驱动，不使用原型演示数据。

## 队列与检查点

首版限制全局同时运行 6 项、每个父聊天同时运行 3 项。其余任务按记录顺序等待名额。全局活动队列最多 128 项，每个父聊天最多 64 项未归档任务，总记录最多 4096 项。一次执行期限为 20 分钟。这些是当前实现常量。

任务、子聊天和首条简报在同一 Room 事务中创建。运行状态、未消费补充、报告和提示词／模型快照保存在 `subagent_runs`；已消费消息与助手输出只保存在现有 `messages` 表，任务详情中的文字是该表的读取投影。消息正文复用现有分块读取，运行报告快照也按 64 KiB 字节块读取，避免单条记录超出 CursorWindow。输出至多每 500 毫秒保存检查点，工具边界和终态也会写入。检查点与最终报告应用现有流修订事件，移除被撤销的采样文字。

消费补充时，前一段助手输出、补充消息、下一段助手位置和消费确认一起提交。复用现有消息分段、sections 编码和工具耗时快照；型号、供应商、请求时间、输入／缓存／输出用量及聊天用量明细随实际执行保存。中间分段不重复计算整轮用量。

应用进程结束后，原先排队或运行的记录标为已中断，不自动重复外部动作。继续任务保留任务及子聊天身份，直接读取子聊天消息表，创建新的执行身份。中断前尚未写入检查点的少量输出不能保证保留。

## 报告交接

父聊天在实际模型执行前连接信箱，模型准备结束本轮时等待仍在运行的子任务或新输入。子代理完成后将带稳定报告标记的内容入父信箱，由主代理继续校验、汇总。用户无需点击“汇总”按钮。

报告先保存到运行表，再投递信箱。父聊天将报告以独立 `agent` 来源保存为聊天消息，同步确认后才标记已接收。重新连接时核对父聊天已保存的报告标记，处理消息已保存但任务确认前进程中断的情形。等待同时观察任务状态与信箱版本，避免遗漏用户补充或完成事件。

父聊天已结束时不自动新建主代理轮次。空闲期间继续某个任务产生的报告保存在任务中，在下一次主聊天轮次接收。活动父轮次的报告自动进入本轮。

## 归档与任务界面

archive_task 接收 task_id、execution_id 与 archived，供主代理归档或恢复终态任务。活动任务需要先停止；归档前等待对应作业完成资源释放，再检查执行身份和删除门。归档不删除子会话、报告或消息，也不阻止父信箱投递和确认。已归档任务需要先恢复，再开始新的执行。

自动归档与成功终态、报告快照在同一保存事务中提交；只在活动状态首次变为成功时触发。恢复到列表、重新连接和确认报告均不会再次触发。任务快照新增带默认值的思考与自动归档字段，原有 Room 30 数据无需迁移或清空。

任务管理区分全部未归档、进行中、已完成、需处理和已归档。“已完成”展示尚未归档的成功任务。所有任务归档后托盘隐藏；正在查看的详情继续显示，可从主聊天报告卡进入详情，再打开任务管理查看归档记录。任务卡摘要收紧为一行，窗口按内容收缩并限制最大高度，长内容继续滚动。

## 取消与资源归属

用户可停止单项执行；停止主聊天会停止其活动子任务。清空或删除父聊天先停止并等待其子执行，再事务删除关联子聊天、消息和运行记录。单项删除、分组删除、角色绑定批量删除共用此路径；删除门保持到父聊天的实际变更结束，期间拒绝新派发与继续，暂停启动该父聊天的排队任务。运行表对父聊天使用限制删除外键，防止绕过清理直接删除父记录。

子执行自己持有前台服务引用和专用模型租约，退出时释放。工具执行随所属请求取消；不会用取消主聊天实例的方式释放子任务。继续执行必须等旧作业清理结束。

子代理沿用父调用的角色卡工具访问规则和常规工具权限检查。记忆查询使用本次任务捕获的记忆空间；常见文件操作的工作区改动记录计入父聊天。

递归委派、共享设备 UI、共享浏览器会话和聊天／模型配置变更在内置执行器入口被限制，CLI 代理和 JS 再次调用内置工具也会经过限制。系统提示同时说明任务和资源边界。通用 shell、脚本、外部 MCP 服务和文件系统仍按现有工具权限工作；此机制不构成操作系统沙箱，也不自动创建隔离工作树。主代理应明确划分文件与资源所有权。

## 会话类型与数据边界

数据库由 29 迁移到 30，增加会话类型和运行关联表。既有聊天与普通分支全部保持普通类型，保留文件夹、归档、最近使用与 token 明细。聊天元数据保存改用 Upsert，避免 REPLACE 删除重插破坏外键关系。

普通聊天列表、文件夹快照、分支查询、内容搜索与角色统计排除子会话；维护清理仍可读取完整库存。普通发送、开场白同步、消息编辑、续写、回答版本、全量保存与单独删除不能改写子聊天；管理操作通过父任务完成。现有任务卡、详情标签和操作布局保持原设计，没有引入上游导航界面。

本次替换尚未发布的首版任务文件方案，不保留双份已消费历史，也不读取草稿版独立 JSON 检查点。完整子会话保存在 Room 中；现有逻辑聊天导出仍只包含所选普通聊天及其中的报告消息，没有升级为包含完整运行关系的会话图格式。原始数据库快照与逻辑聊天导出是不同路径，不能把后者描述为已支持完整子会话跨设备导入。

实际迁移、提供方取消、后台保活、多模型并发与设备上的补充／继续仍需安装验收。
