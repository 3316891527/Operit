# 追加分卷的临时目录对照

本页记录实现阶段的 256 对象小样本。后续已补充 [5,000 与 20,000 个对象的堆和 I/O 对照](scale.md)，用于回答大数量场景。大数量对照中写入耗时下降，但采样已用堆没有降低，累计分配和写入计数增加；不能只用本页小样本推断实际大任务。

当前证据支持“小对象显著减少内容文件数量”。它不支持“Android 内存会大幅下降”或“所有写入都会变快”。分卷增加了 SQLite 索引与持久化开销；首次初始化和较大对象的总耗时可能增加。

## 环境与方法

在同一设备的 Ubuntu 临时目录使用 JDK 17、SQLite JDBC 3.46.1.3、128 MiB JVM 堆运行。对照旧路径采用 SHA-256 命名的独立文件，临时文件写入后执行 fd.sync，再原子移动到目标名。新路径直接调用生产 SnapshotPackStore 和 SnapshotPackIndex，使用真实卷文件、目录同步、WAL 与 FULL 同步的 SQLite 索引。生产 Android 适配器改用 Android SQLite 和 Os.fsync，这里的 JVM 测量不能替代其结果。

最终版本包含最多 256 项位置缓存，新卷头和首个对象一次同步，卷与首个位置一次事务发布，摘要转字节不再创建 32 个子字符串。每个场景执行两轮，每轮固定先旧后新，目录均为全新目录，不覆盖已有结果。未做随机交叉、系统页缓存清理或统计显著性检验。首轮还包含 JVM 与 JDBC 类初始化的影响；第二轮仍包含每个数据库的打开和初始化。

总耗时覆盖构造、写入和关闭；p50、p95 为每次 put 的样本分位数，包含负载字节创建，不包含最后关闭。写后重新打开索引并逐个核对所有不同内容，全部一致。文件数量为关闭连接后的数量，运行时 SQLite 可能另有 WAL、SHM 文件；字节数为文件逻辑长度之和，不等于磁盘块占用。

线程累计分配来自 ThreadMXBean，包含负载数组、哈希与驱动分配；它既不是堆峰值，也不包含全部原生 SQLite 内存、Android ART 内存或内核目录缓存。本轮没有读取、迁移或清理真实快照，没有进行新的设备压力取证。

## 256 个不同的 4 KiB 对象

旧路径创建 256 个内容文件，共 1,048,576 字节。新路径创建 2 个卷，加位置索引共 3 个文件，共 1,144,864 字节。目标 1 MiB 包含记录头，因此 1 MiB 的原始内容需要两个卷。

- 第 0 轮总耗时：647.352 → 1357.559 ms；p50：2.041 → 1.887 ms；p95：3.093 → 3.198 ms；线程累计分配：2,955,112 → 8,079,648 字节
- 第 1 轮总耗时：703.939 → 507.005 ms；p50：2.382 → 1.624 ms；p95：4.817 → 3.096 ms；线程累计分配：1,718,720 → 2,660,656 字节

第二轮耗时降低约 28%，首轮增加约 110%。这是两轮小样本，不能把第二轮单独作为普遍提速结论；累计分配量在两轮中都更高。

## 256 次写入、8 种重复的 4 KiB 内容

旧路径保留 8 个内容文件，共 32,768 字节。新路径保留 1 个卷，加索引共 2 个文件，共 49,488 字节。两条路径都按哈希去重。

- 第 0 轮总耗时：117.122 → 114.112 ms；p50：0.290 → 0.184 ms；p95：1.202 → 0.802 ms；线程累计分配：1,478,656 → 1,544,640 字节
- 第 1 轮总耗时：96.207 → 112.422 ms；p50：0.257 → 0.182 ms；p95：0.901 → 0.519 ms；线程累计分配：1,478,656 → 1,544,640 字节

固定容量位置缓存减少了重复对象查询，但总耗时仍受打开、事务和关闭影响；第二轮总耗时增加约 17%。

## 3 个不同的 700,000 字节对象

旧路径保留 3 个内容文件，共 2,100,000 字节。每两条这样的记录无法放入一个 1 MiB 卷，新路径保留 3 个卷，加索引共 4 个文件，共 2,116,552 字节。

- 第 0 轮总耗时：16.990 → 62.346 ms；p50：4.851 → 10.863 ms；p95：7.761 → 38.435 ms；线程累计分配：2,107,688 → 2,150,816 字节
- 第 1 轮总耗时：18.051 → 60.522 ms；p50：4.684 → 10.462 ms；p95：8.736 → 36.746 ms；线程累计分配：2,107,688 → 2,150,856 字节

这个负载没有减少卷文件数量，还增加了位置库，总耗时约为旧路径的 3.4～3.7 倍。样本只有 3 次写入，p95 接近最大值，不具有大样本分位数的稳定性。

## 证据边界

此前两次实现阶段的测量也都显示文件数减少，但冷启动、重复内容和大对象耗时并不一致。它们用于定位额外索引查询、新卷同步与空卷事务，本页只报告最终实现的完整两轮，不将不同实现的最好值拼在一起。

这里没有测得系统创建大量独立文件的目录缓存占用，不能根据 JVM 分配量推导那部分收益；也没有测得整个应用的峰值内存、长对话流畅度或电量变化。旧路径的原子移动没有单独同步目录，新路径还持久化目录和位置库，两者的持久化工作量有差异。

单独存储内容的文件数下降是这轮明确的交付目标。全局去重、引用检查、恢复和删除语义见 [格式与生命周期](format.md)。若后续继续优化性能，应在独立验证中补充 Android 实际文件系统、更多负载和内存峰值，不能以本轮结果宣称全面提速。
