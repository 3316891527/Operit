# 交接实现与验证

## 已有问题

旧自动续聊队列读取当前成功计数加一，然后等待该数值到达目标。失败或取消不会发出成功计数；成功计数与发送任务完整退出是两个不同的事件，不能用前者表示输出和统计已经收尾。另一条直接发送路径仅凭加载状态已解除就发起下一轮，无法保证上一轮统计保存已退出。

## 实施

统一使用发送任务身份交接。等待发送任务结束后再次检查请求所有权、取消状态和会话占用，才派发一次自动续聊；不增加虚假成功计数，不强行解除旧回合的加载状态。超时保留现有上限并显示未能继续的原因，避免界面停留在含糊的“总结完成”。

普通聊天仅在开始收集时开启自动朗读的情况下建立朗读订阅。原有正文和过程内容继续由主收集及 Waifu 队列处理。发送阶段日志区分正文收集、修订清理、朗读排空、Waifu 排空、输出落盘和统计保存，帮助核实原事件尚未证实的具体阻塞点。

## 验证记录

使用真实 Kotlin 源码、coroutines 1.9.0 与 JUnit 4，启用 JVM 断言 -ea：新增 9 项交接回归，加上既有发送生命周期和空摘要处理回归，共 21 项通过；另以虚拟时间复现旧计数等待在发送已结束但计数未递增时仍等到超时，1 项复现检查通过。失败、忽略和跳过均为 0，不使用生产逻辑替身。

4 个改动 Kotlin 文件的 PSI 语法检查通过；完整 Android 侧的类型检查、编译和 JVM 回归通过分支工作流验证。该次设备事件的旧发送协程挂起点仍缺证据，阶段日志用于新构建再次发生时定位，不能把核心回归等同于实机低频问题已经彻底消失。
