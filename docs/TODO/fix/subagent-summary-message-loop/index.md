# 总结后接收子代理消息导致长会话 OOM

主模型总结后会重新绑定子代理收件箱。原实现为恢复报告和协作消息的消费状态，先读取并解码整个父会话，再提取 agent 消息首行标记。长历史的工具结果和协议负载因此重新进入内存，模型上下文已经压缩也无法避免 OOM。手动继续或应用重启后仍有未消费消息时，同样会触发。

本次只修复投递恢复的数据读取范围：在 SQLite 中按会话、agent 来源和待确认标记查询，仅返回匹配的首行标记。读取失败继续抛出，保留已有报告去重和消息消费语义。查询分批处理，避免超过 SQLite 参数上限；不修改数据库格式、摘要内容和任务生命周期。

1. 在消息 DAO 和历史仓库中增加标记投影，移除报告恢复中的全历史加载。
2. 将父收件箱绑定改为先收集待确认标记，再执行受限查询。
3. 回归覆盖总结前已落库报告、未落库消息、会话与来源隔离、标记边界、重复标记、大历史和批量查询；独立验证数据库异常传播。
4. 复核相邻路径，提交 PR 并启动 Debug 构建和 Android Tests；设备测试 APK 编译和实际执行分别记录。

诊断仅在本机读取现有数据库和日志，仓库不收录私人对话、模型配置及原始日志。现场已确认 OOM，完整业务异常栈未保留。
