# Markdown 扩展检查与验收

## 当前变更

任务列表显示只读勾选框，支持无序、有序列表的嵌套与延续文本。引用块逐层递归解析，内部强调、代码、列表和公式复用原有渲染器。

反斜杠转义、高亮、上下标、括号及可选标题完整的链接接入原生流解析器。表格保存每列的对齐信息，切列时保护代码范围与转义竖线。图片与媒体共用目标解析，在 Android 工作区内按当前文档目录解析相对位置。

完整内容解析阶段建立引用式链接、脚注定义、Setext 标题和目录标记。脚注按首次出现顺序编号，重复引用复用编号；标题和脚注用同一注册表处理页内跳转。依赖全文定义的语法在完整内容阶段确定，流式输入期间不会提前假定后续定义存在。

常见 HTML 块使用已有 HTML 预览组件，保持脚本关闭，并在独立区域内滚动。常见行内样式标签转换为原生文字样式。Operit 专用 XML 内容仍走原有工具卡片组件。Mermaid 类型和绘图实现均未改动。

新文件会话从第一个字符开始，已有会话保留光标与视口。剪切成功只显示剪切提示，复制成功显示复制提示，复用现有多语言资源。显式行号跳转沿用原路径。

## 自动化范围

`ci/markdown-native/run-core.sh` 独立编译并执行生产全文语法、表格与资源地址解析的 JUnit 回归。`ci/markdown-native/run-stream.sh` 编译生产 C++ 流解析器，遍历样例的各个分片位置并检查词元内容，覆盖转义、数学、样式、图片链接、列表、引用与代码保护。

Android Tests 的核心作业使用 Bash 自带数组和路径展开定位 Gradle 8.13 的 Kotlin 编译器，识别到的编译器数量必须为一。原来的 rg 依赖已删除，不需要在 runner 中额外安装搜索工具。现有 Mermaid 核心测试继续执行。

Kotlin PSI 仅验证语法，不进行 Compose 类型解析或应用构建。新增编辑器 instrumentation 验证 744 行文件首次打开的位置与已有会话切换后的光标；普通 JVM 作业不会执行这些设备测试。

## 已知范围

- 双下划线保持 Operit 既有的下划线语义，不修改为标准粗体。
- 任务勾选框用于阅读状态；改变源文件中的勾选需要编辑文本。
- 相对图片位置仅接入具有 Android 文件路径的工作区，聊天没有文件位置上下文。Linux 与远程仓库资源读取不在本轮范围。
- HTML 块是独立预览区域，不声明原生文字引擎完整兼容浏览器 CSS 排版。
- 原生 Markdown 保持明确的语法范围，不声明通过完整 CommonMark/GFM 兼容套件。
