# 终端工具输出精简

## 目标与原状

工具结果原先直接进入聊天标记，标准终端流还会把 start/chunk 和包含同一输出的最终结果拼接。借鉴 RTK 在本地精简开发命令日志的思路，只减少进入模型上下文的重复进度和成功项，使用现有 Kotlin 工具链，不集成 RTK 源码或二进制，不调用其他模型。

分支为 `feat/terminal-output-compression`，目标为 `dev`。本计划的 implemented 表示实现和针对性本地验证完成，完整 Android CI、安装后验证和发行仍需另行确认。

## 实现范围

- 工具聚合保留标准终端、隐藏执行和托管任务的原始数据类型；同命令、同会话且成功的 start/chunk 不再与最终完整输出重复拼接，其他事件和早期失败仍按原规则聚合
- `ToolExecutionManager` 在执行结束后、进入聊天标记前构造独立展示投影，原始 batch、工具通知、脚本返回字段、退出码和会话信息保持原义
- 支持标准终端、隐藏执行、托管任务，以及 `super_admin` 已知终端工具返回的直接或嵌套 JSON 包装；只替换展示副本中的 output
- 只处理 2000 至 256000 字符的内联静态日志，现有 `(saved_to_file)` 或 `output_saved_to` 文件入口直接保留，不读取或展开原文件
- 识别 Gradle 任务进度、Maven 下载、Cargo 编译与通过项、Node 测试通过项、pytest 和 go test 的已知完整行；连续至少四行时保留首尾并标注省略数
- 未知行、空白、保留行颜色和换行原样保留；真正的诊断行及其后缀不再折叠，避免省略错误样本；Gradle 完整任务名中的 Errors 不作为诊断起点
- 简单命令之外的 shell、文件读取、搜索、diff、机器格式选项、JSON、XML、CSV、补丁及未知终端控制序列不进入精简
- 原文入口、包装和 JSON 转义一起计算收益，最终展示须至少节省 256 字符和 20%，且展示负载加错误字段不超过 32000 字符，避免触及已有聊天结果截断上限
- 返回摘要前以 UTF-8 将原输出保存至应用内部 cleanOnExit 目录；标明 read_file_part 的 Android 环境和临时文件生命周期，托管任务已经截断的输出明确标为原工具返回尾部
- 归档失败显式抛出异常，不生成失去原文入口的摘要；该步骤在命令执行完成后，不重新执行命令
- 有序发布只生成一份聊天 XML，保存流与下一次模型请求使用同一份内容；直接绕过工具执行管理器的格式化入口不在此次接入范围
