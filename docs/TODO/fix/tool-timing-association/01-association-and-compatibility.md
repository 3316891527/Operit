# 关联修复与已保存记录兼容

## 修复

`SteeredTranscript.project` 仍按完整消息中的真实位置选取后缀工具，并核对名称与原始标记。选中后只把 `execution.callIndex` 改为后缀局部编号；时钟 ID、开始、完成时长、结束时间及停止状态全部保留。原回答持有的运行状态和原记录不被修改。

`ChatMessage.resolvedSections` 在取得已经附着于工具片段的 execution 后，按当前消息中 ToolCall 的实际顺序规范编号。这也适用于此前已经保存、计时数值仍在但编号为整轮序号的消息。读取不修改原始 sections 列表，不执行批量历史迁移；后续显示、数据库保存和回答版本继续通过同一片段解析边界读取。

缺少 execution 的工具仍占用自己的位置，后面的已知工具不会前移。没有真实记录的历史保持未知，整组记录不完整时继续不显示完整组耗时。

## 回归源码

新增 `SteeredToolTimingAssociationTest` 六项用例，直接调用生产投影、片段存储、消息实体、回答版本和 `ToolTimingIndex`：

- 前缀已有工具，后缀重复相同调用时保存局部编号，并能读到后缀自己的完成耗时
- 后缀包含多个同名工具时分别取得正确耗时，组耗时排除模型等待间隔
- 同一回答多次接收补充，每个后缀重新从零编号
- 数据库消息及回答版本序列化往返后，耗时仍能被显示索引读取
- 旧 JSON 片段携带非零整轮编号时，读取规范编号且不改变原始记录、正文和时间字段
- 历史缺失记录不补零，后续已知工具不前移，完整结果仍可表示完成但整组耗时保持未知

用例使用真实片段和计时索引计算，预先指定的时间值仅用于回归断言，不写入产品或用户记录。

## 范围与验证

生产改动只有消息后缀投影及片段解析两处。Waifu 消息创建、修订和计时展示路径没有修改；没有改动工具执行器、终端观察、数据库结构、费用统计或用户配置。

本轮在本机只进行严格 UTF-8、tree-sitter Kotlin 解析、实际接口源码及差异核对，没有执行 Kotlin/Android 编译、JVM 或设备测试。新增六项回归及完整已有回归交由远端工作流执行，CI 启动不等同测试通过。

三份 Kotlin 文件严格 UTF-8 与 tree-sitter 静态解析无错误，差异检查通过。独立只读复核确认生产修复及六项回归的实际接口、存储换行和快照隔离约定一致；未发现确定类型阻断。运行结果以远端回归为准。
