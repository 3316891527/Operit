# 普通聊天分段后的工具计时关联

普通模式在回复过程中接收补充消息或助手报告后，`SteeredTranscript` 会把后续回复保存为独立消息。后缀中的工具携带整轮 `callIndex`，而显示索引按当前消息从零查找，导致结果能显示已完成，耗时却为空，或后续调用错误关联到前一个调用。

本轮只修复该关联缺陷。Waifu 模式维持当前行为，旧历史真正没有计时记录时继续不显示耗时，分组不完整时不冒充完整总耗时。执行计时区间、并行并集规则及终端观察逻辑保持原义。

## 修复范围

- 普通模式后缀投影时，把已经匹配的工具计时重编为当前消息局部序号，保留真实时钟、开始、时长、结束及停止状态
- 在消息片段解析边界规范已保存计时的局部编号，使此前已保存但编号有偏移的记录仍可显示；不迁移数据库或补造缺失耗时
- 回归从实际消息投影、存储及 UI 计时索引验证单个与多个工具、重复同名工具、多次补充及历史未知记录

## 验证与交付

手机不执行编译、JVM 或设备测试。完成 UTF-8、Kotlin 解析、接口与差异检查后，提交独立分支并创建面向 `dev` 的 PR，派发远端 `assembleDebug` 与测试；登记启动后停止查询进度。代码核对、远端结果及设备体验分别报告。

实现与回归记录见 [01：关联与兼容](01-association-and-compatibility.md)。
