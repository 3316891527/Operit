# Operit Kong 1.12.2+29 紧急修复

修复打开 Linux 目录、读取文件和执行工具时，被工作区文件监控的同步扫描拖住的问题。

## 本次修复

- 移除通用工具执行前后的同步工作区扫描，文件浏览器与聊天工具直接执行并返回结果
- 保留文件工具的精确写入快照、终端文件采集和后台事件观察，读取目录不再为了历史采集等待全局观察锁
- 合入前序工作区历史优化：操作记录增量保存、约 1 MiB 快照分卷、有界批次提交及历史分页
- 合入前序 Waifu 连续过程布局与已清理历史处理修复
- 修复总结完成后的自动续聊交接，等待上一轮消息落盘和统计收尾后再发送
- 工作区大文件大小补充 GB、TB 显示，继续沿用 1024 进位和一位小数

## 更新与数据

版本为 `1.12.2+29`，内部版本号为 `85`，沿用 `com.ai.assistance.operit.kong` 包名与既有固定签名。发行流程从 `1.12.2+28` 生成增量更新，同时提供完整 `app-kong.apk`。

旧操作 JSON 会在新存储入口使用时逐条迁移，保留原记录身份、时间、来源和快照引用。成功迁入新操作表并删除源 JSON 后，旧 APK 不能读取这部分已迁移的操作历史。

工具耗时显示的间歇缺失尚未修复，用户反馈最早出现于 2026-11-24 北京时间 18:50；本次先交付监控阻塞修复，再观察新版表现。

正式发布工作流在公开发行前执行 JVM 回归、仪器测试编译、APK 包名和签名校验、离线资源核对与增量包还原校验。仪器测试编译不代表已经执行设备测试；此版本没有把任何真实用户历史用于开发验证。
