# 运行时、结果交接与使用边界

[返回计划](index.md)

## 任务与执行身份

`SubagentCoordinator` 是应用级任务所有者。每个任务关联独立的 Room 子聊天，并保存父聊天、发起工具调用、提示词快照、模型池引用、工作区、角色卡与记忆空间。任务 ID 与子聊天 ID 分开保存；模型执行与工作区变更使用真实子聊天身份，再由关联记录归属到父聊天。任务身份、每次执行身份和父工具调用身份分别保存。

`spawn_task` 从可信工具执行上下文取得调用方，不接受模型自报的父聊天或工具调用身份。同一次父工具调用不会重复派发。补充、停止、等待、继续与归档／恢复必须匹配当前执行身份，防止迟到请求影响新执行。

每次执行使用独立的 `EnhancedAIService` 实例与输入信箱。子代理接收独立简报、自己的历史和补充；派发时可用 fork_turns 明确选择继承当前父轮次的背景，默认 none 不继承。任务列表、详情和报告均由真实任务状态驱动，不使用原型演示数据。

## 队列与检查点

全局和每棵根会话树的并发可配置，默认分别为 6 和 3；其余任务按排队时间和稳定身份排序；等待后恢复的执行先重新取得名额。等待中的代理保留协程但不占采样名额，终态作业直到清理完成仍占名额。修改并发用于后续调度，缩小限制不取消已有执行。每次执行时限在派发或继续时快照，默认 20 分钟，可设为 1～120 分钟，排队时间不计入。全局活动队列最多 128 项、每个父聊天最多 64 项未归档任务、总记录最多 4096 项，容量限制仍固定。

任务、子聊天和首条简报在同一 Room 事务中创建。运行状态、未消费补充、报告和提示词／模型快照保存在 `subagent_runs`；已消费消息与助手输出只保存在现有 `messages` 表，任务详情中的文字是该表的读取投影。消息正文复用现有分块读取，运行报告快照也按 64 KiB 字节块读取，避免单条记录超出 CursorWindow。输出至多每 500 毫秒保存检查点，工具边界和终态也会写入。检查点与最终报告应用现有流修订事件，移除被撤销的采样文字。

消费补充时，前一段助手输出、补充消息、下一段助手位置和消费确认一起提交。复用现有消息分段、sections 编码和工具耗时快照；型号、供应商、请求时间、输入／缓存／输出用量及聊天用量明细随实际执行保存。中间分段不重复计算整轮用量。

应用进程结束后，原先排队、运行或协作等待的记录标为已中断，不自动重复外部动作。继续任务保留任务及子聊天身份，直接读取子聊天消息表，创建新的执行身份。中断前尚未写入检查点的少量输出不能保证保留。

## 父轮次背景继承

spawn_task 的可选 fork_turns 接受 none、all 或 1～64 的整数；默认 none。all 表示父模型当前可用的上下文，已经压缩的历史以现有总结为准，不重新读取压缩前的所有原始消息。整数从最近相应数量的真实用户轮次开始选择。当前用户输入包含在模型请求边界的不可变快照中；并行工具不会直接读取正在修改的历史列表。

继承仅保留用户输入、最终助手正文和总结，去除父系统提示、工具调用／结果、思考与宿主报告。已存储助手消息拆成工具回放时保留来源标记，工具前的过程文字及宿主告警不会误计为最终答复或用户轮次。宿主报告禁止与真实用户输入合并，防止来源标记污染用户内容。

过滤后的背景带明确边界，以一条 summary 消息与真实子聊天、运行记录和新任务简报同事务落盘，时间戳先于新简报。背景正文连同边界最多 200000 字符，超限或没有可继承内容时明确拒绝派发，不静默截断。子代理仍使用独立提示词；继续时读取已有背景和子历史，不再次复制父对话。详情显示继承范围，子会话将 summary 标为背景与总结。

## 报告交接

父聊天在实际模型执行前连接信箱，模型准备结束本轮时等待仍在运行的子任务或新输入。子代理完成后将带稳定报告标记的内容入父信箱，由主代理继续校验、汇总。用户无需点击“汇总”按钮。

报告先保存到运行表，再投递信箱。父聊天将报告以独立 `agent` 来源保存为聊天消息，同步确认后才标记已接收。重新连接时核对父聊天已保存的报告标记，处理消息已保存但任务确认前进程中断的情形。等待同时观察任务状态与信箱版本，避免遗漏用户补充或完成事件。

父聊天已结束时不自动新建主代理轮次。空闲期间继续某个任务产生的报告保存在任务中，在下一次主聊天轮次接收。活动父轮次的报告自动进入本轮。

## 归档与任务界面

archive_task 接收 task_id、execution_id 与 archived，由根代理或祖先归档／恢复整棵终态子树。全部活动下级需要先停止；归档前等待对应作业完成资源释放，再检查执行身份和删除门。归档不删除子会话、报告或消息，也不阻止父信箱投递和确认。已归档任务需要先恢复，再开始新的执行。

自动归档与成功终态、报告快照在同一保存事务中提交；只在活动状态首次变为成功时触发。恢复到列表、重新连接和确认报告均不会再次触发。任务快照新增带默认值的思考与自动归档字段，原有 Room 30 数据无需迁移或清空。

任务管理区分全部未归档、进行中、已完成、需处理和已归档。“已完成”展示尚未归档的成功任务。所有任务归档后托盘隐藏；正在查看的详情继续显示，可从主聊天报告卡进入详情，再打开任务管理查看归档记录。任务卡摘要收紧为一行，窗口按内容收缩并限制最大高度，长内容继续滚动。

详情的任务目标、报告、子会话和当前输出使用现有 Markdown 组件渲染，型号与提示词名称保持纯文本。详情正文与卡片摘要在显示前经过主聊天同一协议过滤器，隐藏提供方 meta 负载并保留闭合代码示例；原始消息继续用于保存与模型请求。独立详情清空外层聊天时间线的渲染片段，避免复用错误消息；紧凑卡片继续展示一行摘要。

## 取消与资源归属

用户可停止指定执行及其全部下级；停止主聊天会停止整棵活动树。根代理可以控制所有后代，中间代理只能控制其后代；同根其他分支允许观察与通信。清空或删除父聊天先停止并等待其子执行，再事务删除关联子聊天、消息和运行记录。单项删除、分组删除、角色绑定批量删除共用此路径；删除门保持到父聊天的实际变更结束，期间拒绝新派发与继续，暂停启动该父聊天的排队任务。运行表对父聊天使用限制删除外键，防止绕过清理直接删除父记录。

子执行自己持有前台服务引用和专用模型租约，退出时释放。工具执行随所属请求取消；不会用取消主聊天实例的方式释放子任务。继续执行必须等旧作业清理结束。

子代理沿用父调用的角色卡工具访问规则和常规工具权限检查。记忆查询使用本次任务捕获的记忆空间；常见文件操作的工作区改动记录计入父聊天。

多层委派受配置深度与可信根身份约束。共享设备 UI、共享浏览器会话和聊天／模型配置变更在内置执行器入口仍被限制，CLI 代理和 JS 再次调用内置工具也会经过限制。系统提示同时说明任务和资源边界。通用 shell、脚本、外部 MCP 服务和文件系统仍按现有工具权限工作；此机制不构成操作系统沙箱，也不自动创建隔离工作树。主代理应明确划分文件与资源所有权。

## 会话类型与数据边界

数据库由 29 迁移到 30，增加会话类型和运行关联表。既有聊天与普通分支全部保持普通类型，保留文件夹、归档、最近使用与 token 明细。聊天元数据保存改用 Upsert，避免 REPLACE 删除重插破坏外键关系。

普通聊天列表、文件夹快照、分支查询、内容搜索与角色统计排除子会话；维护清理仍可读取完整库存。普通发送、开场白同步、消息编辑、续写、回答版本、全量保存与单独删除不能改写子聊天；管理操作通过父任务完成。现有任务卡、详情标签和操作布局保持原设计，没有引入上游导航界面。

本次替换尚未发布的首版任务文件方案，不保留双份已消费历史，也不读取草稿版独立 JSON 检查点。完整子会话保存在 Room 中；JSON 逻辑备份格式升级至 4，带任务的根聊天在同一数据库快照中读取完整子树、消息、变体、报告及邮箱，分条输出。图导入校验后创建新根和新身份，活动执行改为中断，不自动运行；普通旧档继续可读。CSV、Markdown 和 HTML 保持原有展示导出用途。模型池、凭据和工作区文件不随会话图复制。

通信工具 send_agent_message 按同根任务 ID 或路径寻址，main 或 / 表示主聊天。消息先持久化，再投递真实执行信箱；默认不启动空闲目标，wake=true 明确创建一次新执行，归档的祖先必须先恢复。空闲主聊天只保留邮件，在下一轮接收。单条最多 10000 字符，每个持有节点最多 64 条未消费邮件和 1024 条总邮件。

wait_task、wait_agents 和父轮次结束等待复用让出／重新取得名额的过程，拒绝依赖环。wait_agents 接受 tree 或 mailbox，单次最多 30000 毫秒，返回 mailbox、idle 或 timed_out。零超时也先观察当前输入。子代理消费报告或邮件时，与前一段输出、新消息和下一段位置同事务提交；主聊天仍先保存 agent 消息再确认，重连时通过稳定标记恢复确认。

实际迁移、提供方取消、后台保活、多模型并发与设备上的补充／继续仍需安装验收。
