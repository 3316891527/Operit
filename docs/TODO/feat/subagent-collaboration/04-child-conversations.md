## 当前情况与目标

首版把任务、执行状态和消息放在独立 JSON 文件中，没有真实 Room 子聊天。继续执行与任务详情依赖这份文件，不能使用现有消息分段、工具耗时和聊天统计。

本次仅完善完整子会话的数据层，保留现有任务卡和详情的布局、入口及操作。参考上游 #1482 的父子关联与事务设计，在本分支数据库 29 版上迁移，不移植其界面、代理树通信、上下文复制或 v5 会话图导入导出。

## 实施单元

1. 数据库 29→30：增加普通／子代理会话类型、运行关联表和索引。旧聊天及普通分支保持普通类型，保留文件夹、归档、最近使用和用量明细。聊天保存使用不会删除重插的写法，父子关联限制绕过生命周期的删除。
2. 事务存储：任务与子聊天一同创建；提示词、模型、运行状态、未消费输入和报告持久化到运行表；已消费输入与助手输出只保存在现有消息表。停止使用独立任务文件，当前草稿方案直接迭代。
3. 真实执行：持久化首次简报、工具过程、补充边界、流修订后的检查点、终稿、模型与真实用量。继续执行直接读取子聊天，进程重启保留已写记录并标记中断，不自动重复外部操作。
4. 数据保护：普通列表、搜索、分支与角色统计排除子会话；普通发送、开场白、编辑及全量保存不能改写子聊天。清空、单项删除、分组和角色批量删除先停止执行，再清除关联子聊天。
5. 交付：更新运行文档与 PR #235，推送同一分支并派发 APK 构建。提供构建入口，不轮询工作流进度；实际设备验收结果另行记录。
