# 模型与对话设置设计

现有模型工作区在同一份配置下展示连接、参数、功能分配三个页签，而功能分配实际作用于全局。上下文与总结位于设置首页的另一个入口，其大部分参数又属于模型配置。此次先重新设计信息层次，再决定 Android 页面的实现方案。

- [单文件交互设计稿](design.html)
- [页面结构与后续实现范围](01-design.md)

## 本轮方案

设置首页以“模型与对话”为统一入口。一级工作区使用模型配置、功能分配、上下文与总结三个页签；连接和参数进入所选配置的详情页面，避免四个页签同时承担配置编辑与全局功能设置。

模型配置支持示例配置的分组筛选、搜索、添加、重命名、复制、删除和模型列表编辑。连接页展示端点、密钥、服务方式与五项请求能力；参数页提供常用参数和请求队列的编辑。密钥池仅演示状态，完整思考匹配规则和自定义参数仅展示分区，不宣称已完成这些编辑器。

功能分配保留现有十二种功能，按对话与整理、记忆与检索、工具与辅助、多模态理解分组。支持搜索、待检查筛选、按配置筛选、跨分组选择配置与具体模型，以及思考覆盖的保存和取消。记忆向量保留未配置状态，不展示普通聊天模型的思考控件。功能测试仅提供四种示例结果，不发送请求。

上下文与总结明确区分正在编辑的配置、全局总结模型分配、全局历史媒体保留。切换配置保留各自的上下文长度、自动总结阈值、按消息条数触发及摘要结构。摘要补充规则、四个板块和对话回顾放进居中编辑窗口，支持保存与取消。

设置首页另展示数据与资源、工具与连接、应用与诊断的入口归属建议；其他设置页面在本稿中不重新实现。离线资源内部改造与终端环境预装继续后置。
