# 快照导入后重绑主题脚本

跨应用包名或 Android 用户恢复数据快照时，脚本文件已在归档内，但 `custom_theme_script_uri` 未参与资源迁移，仍引用原安装目录。主题工作室检查当前私有存储边界时因此拒绝读取。

在现有 `data/backup` 中登记主题脚本资源，并将全局、角色卡及角色组的脚本偏好纳入已有恢复路径。脚本 ZIP 已封装源码与素材，备份时保持完整包；恢复仍写入当前应用的 `files` 根目录，保持原文件名和主题读取边界。

## 范围与兼容性

- 新导出使用现有清单资源映射登记脚本，不更改快照格式版本
- 已有快照按来源包名与归档文件定位脚本，导入前重写偏好引用
- 复用现有的缺文件报告和路径检查，不添加替代主题或放宽私有目录边界
- 不修改思考档位设置、主题工作室界面或脚本内容

## 验证

使用 Kotlin 2.0.21、JVM 17 和 DataStore 1.0.0 独立编译真实媒体恢复实现及仓库 JUnit 用例。原实现执行 13 项，新增的 3 个脚本场景失败；修复后 13 项全部通过。覆盖全局、默认角色、自定义角色和角色组共用脚本、跨包名与 Android 用户、文件缺失和非法 URI。

实际快照的三处角色主题偏好共用一个完整脚本包。以真实偏好和文件在临时目标目录重放恢复计划与 protobuf 重写：旧实现不生成原始脚本恢复计划，修复后生成一项；补充现有清单映射后，旧实现与新实现均能重写三处引用，其余偏好值和脚本字节保持一致。此验证没有启动 Android 界面。

仓库外修复快照仅补充一项清单映射，4297 个 ZIP 条目 CRC 全通过，其他 4296 个压缩载荷保持原字节。私有快照、偏好、脚本及审计输入均不提交仓库。差异空白、UTF-8 和新增文档链接检查通过。

Debug 构建使用 `assembleDebug`，同时发起 Android Tests。登记启动结果后停止查询工作流进度；完整 Android 构建、全量测试和设备导入后的工作室界面仍待确认。
