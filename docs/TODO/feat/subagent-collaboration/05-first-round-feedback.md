# 首轮体验修正

[返回计划](index.md)

用户已安装首版并完成简单并行任务验证。本轮根据截图完善模型选择、每执行思考调度、尺寸和归档，不改变已确认的主聊天与任务详情设计。

1. 添加模型仅列出当前模型配置组内的配置，以配置为折叠单元展示型号；已加入的全局模型池条目继续保留。
2. 主代理通过工具在派发或继续时选择思考开关和实际档位。目录公布每个型号支持的档位，严格校验并传递到所有模型请求，不新增固定思考强度界面，不修改主模型偏好。
3. 收紧模型池卡片、报告卡及任务窗口的间距和宽度；任务列表高度随内容收缩并限制最大高度，长列表继续滚动。
4. 增加带执行身份校验的归档／恢复工具。增加成功完成后自动归档的全局选项，默认开启；失败、中断、取消保留待处理。归档不删除历史、不影响报告交接；未归档任务清空时底部托盘隐藏，报告入口仍能查看归档记录。
5. 任务管理增加已完成筛选，区分活动、成功完成、需处理和归档；参考 Operit-Ry 的生命周期与思考参数传递方式核对本轮实现。

交付沿用 PR #235，仅派发 assembleDebug，不发布发行包；确认派发后不轮询进度。验证以代码核对、差异检查及该 Debug 构建为准，用户首版简单验证不能替代本轮设备验收。

## 本轮落实与核对

模型选择器已接入当前配置组，配置折叠、已选数量和搜索均沿用真实配置，展开型号采用惰性列表。已有模型池条目继续按全量配置核对有效性，避免切组后误报失效。

思考选择作为单次执行快照保存，模型目录提供实际档位；派发、继续、执行开始与实际租约均检查选择。首次请求和所有工具后续轮次传入覆盖值。没有新增固定思考强度界面或全局偏好写入。

新增 archive_task；界面归档／恢复同样传入执行身份。成功终态与自动归档一起持久化，后续确认报告不会再次归档。全局开关默认开启，工具可单次覆盖；旧任务快照默认不自动归档。

任务卡宽度由 246dp 收到 220dp，摘要压为一行。任务窗口最大宽度从 720dp 收到 560dp，宽度占比从 96% 收到 90%，最大高度为屏幕的 82%，正文按内容收缩。任务管理新增已完成，托盘在没有未归档任务时隐藏；详情与归档历史入口保留。

参考 [Operit-Ry 固定修订](https://github.com/liyunkkk/Operit-Ry/tree/74a3b661c6d3475c90f4325b80e3c0b4508b3099) 的 CollaborationModelParameters、CollaborationCoordinator 与 SubagentManagement，核对思考参数、终态交接和完成／归档筛选；没有移植其界面或把参考仓库的测试当成本轮结果。

已补齐中英资源和 10 项思考／快照兼容 JVM 回归用例；验证及待设备确认项目见[交付记录](03-delivery.md)。
