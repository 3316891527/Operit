# 压缩发布、隐藏路径文件与媒体预览反馈修正

[返回计划](index.md)

## 目标与范围

按设备反馈修正压缩名称及 getFileStore 错误，合并隐藏管理入口，提供可编辑的完整隐藏路径文本文件，去掉顶部页签按下时的矩形阴影，并让视频按可用区域等比例放大。继续使用当前分支与 PR，不改变文件路由和编辑器既有能力。

- [x] 压缩失败显示目标、步骤与原因，完整异常继续记录日志
- [x] 删除独立管理隐藏项入口及重复窗口，在显示手动隐藏项下增加编辑隐藏路径文件
- [x] 隐藏路径按环境隔离，文本逐行保存完整路径，长按隐藏、取消隐藏和手动编辑同步生效
- [x] 保留已有隐藏记录与其余浏览、编辑设置

## 验收边界

重点覆盖单文件、目录、复合扩展名、ZIP 发布与普通改名、同名冲突、取消、隐藏路径中的空格及不同来源、编辑与隐藏状态同步、页签关闭按钮与按下反馈、竖屏和横屏视频。图片只作为随消息提供的视觉输入，不读取附件路径。本地不执行编译、构建或测试；静态、回归源码和远程执行结果分开记录。确认工作流运行记录建立后停止查询进度。


## 实现说明

压缩名称主体与扩展名分开。普通文件默认去掉原扩展名，复合压缩后缀按整体处理，带点的目录名、隐藏文件及无后缀文件保留原名。输入框右侧显示所选格式的只读后缀，输出自动拼接，例如 prompt.md 默认得到 prompt.zip，切换格式得到 prompt.7z 或 prompt.tar.gz。

截图中的 getFileStore 对应本机移动前的 Files.getFileStore 调用，用于比较来源和目标是否属于同一文件系统。Android 的默认文件系统提供器不支持这一查询，裸异常信息只有方法名。归档先写入并校验临时文件，再通过共享改名路径发布，所以该调用同时影响压缩发布、另存为发布和普通改名。现改用 Android Os.stat 的 st_dev 比较设备号；同设备仍使用直接移动，跨设备仍走既有传输操作，不捕获异常后重试其他方案。压缩创建失败显示文件名、步骤、目标环境及路径、异常类型与原因链，保留原异常供日志诊断。取消继续独立传播，失败或取消不覆盖已有目标。

删除独立管理隐藏项入口及旧窗口，保留显示点文件和显示手动隐藏项，在其下增加编辑隐藏文件。该入口直接打开现有文本编辑器，保存即生效。每个来源独立使用 UTF-8 文本文件，目录为应用 files/workspace_hidden_paths，Android 对应 hidden_android.txt，Linux 对应 hidden_linux.txt，授权或远程来源名称按环境编码。每行精确记录完整路径，不增加通配符语法，空行忽略，路径中的 Unicode 和空格保留。文件名与来源隔离，同名根路径不互相影响。

已有 JSON 隐藏记录首次导入文本文件，初始化标记在导入完成后提交；清空或删除某个环境文件后不会再次从旧记录恢复。长按隐藏和取消隐藏修改同一组文本文件。浏览偏好读取文本文件的当前内容，其他设置更新不覆盖已手动编辑的规则，仍保留收藏、首页和编辑器偏好。文件观察器监听保存及原子改名，触发浏览器和选择器更新；文本文件是生效来源，原 JSON 字段保持结构兼容。

页签外层保留点击高度和选择语义，移除外层按下指示，避免圆角框外出现矩形遮罩。文件关闭和未保存标记仍保留。视频容器去掉 16dp 留白及播放器 420dp 高度上限，播放器占用工作区全部可用空间，原生视图使用 MATCH_PARENT，保留等比例 FIT 显示，避免裁掉视频内容；横竖屏和窗口尺寸变化由容器重新测量。
