# 聊天导入优化

JSON 导入从每会话全量对象改为逐消息读取。为兼容消息字段在会话元数据前出现的合法备份，先把原始消息按 JSON token 写入应用缓存中的临时暂存文件，读完元数据后在单会话数据库事务内按有限消息数和文本量批次保存。异常或取消回滚当前会话，并清理临时文件。

旧版 `content` 和当前 `sections` 共用直接生成消息对象的解析逻辑，消除 sections 对象重新编码为 JSON 再解码的往返。保留消息顺序、候选回复、模型、用量、时间及文件夹绑定；旧聊天数组继续兼容。

保存批次最多 32 条消息，并以 sections 与搜索文本合计 256 Ki 字符作为额外批次预算；单条超出预算的消息独立写入。峰值仍受最大单条消息及其候选回复大小影响，暂存会增加本地磁盘读写，缓存空间不足时当前会话不会提交。

独立 JVM 验证使用 Kotlin 2.0.21、JDK 17、Parcel 和 Room 注解桩，覆盖真实解析、转换与实体分批生成，不执行 Android UI 或 Room 数据库。两份 v2/v3 样本解码后逐字段一致；约 52 MiB、50000 条消息的合成备份在 64 MiB 堆上限内处理完成。
