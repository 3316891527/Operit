# 语音输入能力拒绝与临时错误显示

报告中的对话音频和音频理解请求被服务端拒绝，错误为 `unsupported content type ... input_audio`，外层 HTTP 为 503；之后已有 STT 路径完成识别。应保留既定输入处理顺序，对明确内容类型错误停止换钥/重发，并把可恢复音频尝试的通知限制在实际采用的响应中。已解析的语音历史继续复用转写，不重新发送音频。

实现范围为请求重试策略、语音响应编排、已解析语音输入与相应回归；不修改硅基转写上传格式或持久化模型能力开关。验证由仓库工作流执行，本地不构建或运行测试。

## 实现

- 请求重试策略将明确的 `unsupported content type` 识别为请求内容错误，即使网关外层返回 503 也不重复换钥发送相同音频；普通 503、限流和传输故障保留原有重试策略
- 语音编排在收到音频回答正文前暂存该尝试的重试通知，采用音频回答时再发布；进入既有转写路径时不把已放弃尝试的通知留在聊天中。文字请求自己的通知和最终异常仍正常报告
- 已持久化转写的语音在历史和手动重试时直接使用文字；未转写录音仍遵循实际模型配置的音频开关。只有附加钩子文字时不视为已识别
