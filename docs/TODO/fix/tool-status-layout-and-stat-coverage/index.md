# 工具状态同排、过程折叠与统计样本覆盖

## 背景与目标

已发布版本的普通回复同时包含总用时折叠标题与内部工具组折叠。展开总用时后仍可能看不到调用；单项工具另起一行显示状态，造成重复的“已完成”和不清楚的归属。统计总览还会因少量历史缺失字段而隐藏整个比例。

本次修复让总用时接管其完整覆盖的工具组，把单项状态与耗时放进工具标题同一行，并让统计比例使用明确可计算的样本、显示数据覆盖。

## 实施范围

- 普通聊天时间线与悬浮窗共用过程组展开逻辑。总用时完整覆盖的组铺平，工具保留原节点索引、稳定标识、子流与详情入口；跨界组继续整体显示。
- 没有总用时控制的流式回复、设置关闭和独立渲染继续使用原来的组控制。Waifu 保留专用过程入口。
- 单项工具状态与工具名、参数预览同排，保留实时计时和详情弹窗。窄屏先压缩参数预览与名称；不再在单项状态里显示调用次数。仍显示的组标题明确为“本组工具已完成”，不表示整条回复或工具业务结果成功。
- 成功率为成功次数除以状态明确的请求数。正常结束但未确认成功的 `COMPLETED` 只进入分母；历史空状态和不识别状态单独显示为未知。
- 缓存率仅汇总同一批输入拆分完整、非负的成功用量事实，使用缓存读取 Token 除以这些样本的全部输入 Token。完整历史事实沿用既有规范化；失败、取消及未确认用量的诊断数据不混入分母。卡片说明完整与不可用的请求数。

## 兼容性

保持既有消息、工具执行计时和数据库格式，不回写历史记录。新增统计汇总字段有默认空值；没有覆盖数据时明确不显示缓存比例，不从不同样本的字段总和拼出比例。保留零命中与无有效输入的区别。

本次不修改应用版本号，不改写已经发布的 2.0.0 更新日志；修复通过独立 PR 交付。

## 验证安排

回归源码覆盖总用时展开与收起、多轮工具和旧折叠选择、跨界组、原索引与稳定标识、单行宽度分配、实时状态更新与详情点击，以及未知历史、互补缺失输入、失败取消、零命中、完整筛选范围与分页隔离。

静态检查、独立复核及远端工作流的启动信息在交付回执记录。设备回归源码与 JVM 回归源码分别保留，不将静态检查或设备测试编译等同于实际设备执行。
