# 总结完成后的自动续聊交接

设备日志显示，摘要生成、保存和上下文窗口刷新已经完成，续聊却排队等待上一回合的成功计数。2026-11-23 的观察中，队列从 22:53:39 等到 22:55:49 的取消操作，期间没有新的模型请求。现有日志不足以还原旧发送任务当时挂起在哪一个协程，因此不把计数等待缺陷直接认作该次事件的完整根因。

## 修改意图与范围

自动续聊改为等待原发送任务的完整终态，涵盖输出落盘和统计保存，避免失败路径没有成功计数而空等，也避免加载标志已清除时提前重置下一轮统计。请求被替换或用户停止后不得恢复旧续聊，超时必须显示交接未完成。

普通聊天关闭自动朗读时不创建全文 Markdown/XML 朗读解析订阅，减少长工具回合的无用工作。补充文本、修订、朗读、Waifu 队列、持久化和统计阶段日志，只记录任务身份、阶段与耗时，不记录提示词或密钥。

沿用现有对话、摘要持久化格式和设置。本次从 dev 单独建立 fix/summary-auto-continuation 分支，不改动已提交的 Waifu UI 方案，也不修改终端文件监听。
